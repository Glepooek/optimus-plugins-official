# Changelog

## [2.0.0] - 2026-09-07

### Removed
- **第五步「同步文档数字」整节废除，6 处同步点归零。** 原设计把 tips 条目总数冗余写进 6 个展示性文件（两份插件市场描述、`hooks/README.md`、`.kiro/steering/` 三份），每轮 sync 手工追平。该设计已导致两次失准事故：同步点清单 2→4→6 处两轮漏项，其中 `.kiro/steering/{structure,product}.md` 两处措辞为「N **条使用技巧**」（中间插字，旧窄正则命中不到），**从未被任何一轮 sync 更新过**，长期停在 425 而真实值为 276。根因不是同步流程不够严密，而是**派生值不该被写死在文档里**——6 处数字已全部改为不含数字的表述（如「SessionStart（技巧智能轮播）」），与根 `README.md`「有意不含数字，避免多处同步失准」的既有做法拉平
- 随之删除：同步点清单表、全仓库扫描的 Bash/PowerShell 双写命令、11 行 ✅/❌ 甄别表、`Select-String` basename 混淆的注意事项、「数字不一致」CHECKPOINT。SKILL.md 净减约 58 行

### Changed
- **第五步改为「写入后完整性校验」**，只保留与数据正确性相关的部分：原三重校验（`grep -c '^{'` == `wc -l` == 旧数+新增−删除）升级为**四重**——新增第 2 项逐行 JSON 解析（此前只数行数，某行 JSON 语法错误能通过校验）、新增第 4 项孤儿引用反查（被删条目的标识符可能在其他条目正文中被提及，删除后该引用悬空；本轮无删除时跳过）
- 第五步开头加固定告示与 ⛔ 禁令，明确「不要重新往任何文件添加条目总数」并给出理由，防止后续维护者出于「文档更详细」的善意复原该设计
- 第六步摘要移除「📄 已同步：6 处文档」行，改为报格式校验结果；`📊 条目总数` 保留但标注「即时统计，不写入任何文档」
- 反例黑名单「用估算数字代替实际计数更新文档」改写为「往任何文档写入 tips 条目总数」，从「怎么算准」变为「不该写」
- 第三步零变更总闸、frontmatter `description` 中对「文档数字同步」的引用一并改为「格式校验」

### Fixed
- **修正开篇「无需人工干预」与三处强制 CHECKPOINT 的直接冲突**（darwin-skill 第三轮扫描发现，全文最强矛盾）。原文声称「全自动同步，无需人工干预」，但流程含 3 个阻塞式人工确认点（第一步 >30 版本询问、第二步空文件确认、第四步写入前 CHECKPOINT）。执行者读完开篇会形成「不该停下来问」的预期，自动化调度场景下更可能据此跳过 CHECKPOINT——**这是会导致未经确认改写唯一真源的安全隐患**。已改为「抓取、判定、写入、校验全自动，但写入前必须经一次人工确认」，并在开篇加一张 3 行表列出全部阻塞点、触发条件与跳过后果，显式规定无人应答时超时终止而非默认放行
- 修正「零变更时是否提交」这一事实的**第四个副本**：第一步兜底表原写「awk 截断后输出为空 → 等同于触发零变更总闸，跳过后续所有步骤」，与总闸「仍须推进锚点并单独提交」字面冲突。实际上两者是不同场景——该行是「无新版本可处理」（锚点已等于最新版，无需推进也无可提交），总闸是「有新版本但均无实质变更」（仍须推进）。已改写为显式区分二者
- 修正第六步摘要与版本号职责外交的冲突：摘要模板原要求输出「两份 plugin.json {旧版本} → {新版本}（Patch）」，但摘要展示在调用 `commit-cc-plugin` **之前**，且第五步与黑名单两处均声明版本号由后者判定、本 skill 只交接事实——等于要求本 skill 先说出一个它声明自己无权决定的值。已改为「待 commit-cc-plugin 按触发矩阵判定（预期 Patch）」
- 修正摘要中一句**不成立的断言**：第五步规定「本轮无删除时跳过第 4 项（孤儿引用）」，但摘要固定打印「四重全过（…无孤儿引用）」。已改为条件表述「孤儿引用{无命中／本轮无删除不适用}」
- 明确四重校验失败时三种动作的优先级：原文「回第四步修复」「校验不过而中止」「停止不进入第六步」三种说法并存而无先后，已统一为「先修复重跑 → 修复无效或原因不明则停止，不进入第六步、不推进锚点」
- 修正 1.6.0 引入的一处**事实错误**：第二步残影检测阈值说明中的「实测 276 条」被机械改成 263。该数字是 2026-09-04 那次实测的**样本量**（0.263 与 0.333 两个覆盖率就是在 276 条库上测得），属历史取证而非派生值，改成 263 使这句话变成假陈述。已还原为 276 并加注「属历史取证，不随库存变化更新」
- `test-prompts.json` 三条 `expected` 更新为现行行为（id 1 / 3 / 4）。此前描述「同步 6 处文档数字」「Patch 版本号」等已废除的步骤，留着会成为恒定失败的失效断言，误导下一轮验证。**这与「不重写既有测试条目」的规范不冲突**——该规范防的是为迁就实现而放宽断言，此处是被测行为本身已被删除，断言失去指向对象
- 同时修正 id 3 一处**原有的自相矛盾**：其 `expected` 写「不调用 commit-cc-plugin」，但第三步「🚦 零变更总闸」明确要求零变更时仍需推进 `.last-synced-version` 并单独提交。该矛盾早于本次改动存在，已按 skill 现行逻辑更正为「仍推进锚点并单独提交」
- 反例黑名单「0变化时仍然提交」条目原写「不调用 commit-cc-plugin」，与零变更总闸同样冲突（该事实的第三个错误副本）。已改写为区分「不提交 tips.jsonl 改动」与「仍须为锚点单独提交」，并加「这不是无意义 commit」的反驳堵住按旧直觉改回的路

### Notes
- 本版为 **Major**：删除了一个用户可见的流程步骤（第五步的文档同步职责），调用者若依赖「sync 会自动更新市场描述里的条目数」这一行为，该行为已不存在
- CHANGELOG 仍缺 1.4.0 / 1.5.0 记录，本次不代为补写

## [1.6.0] - 2026-09-07

### Added
- **第三步新增「👁️ 可感知性门」**，与既有「环境可用性门」并列为新增前的第二道门禁。判据是一个问题：「用户改了这个配置/用了这个功能，怎么知道它起作用了？」答不出验证闭环即判 ⏭️ 跳过。配 9 行判定表（界面可见 / 有命令可查 / 会撞到的行为变化 → 通过；只在 OTel 后端可见 / 默认值碰不到 / 静默生效 / 企业专属 / 仅兼容多写法 / 已失效死配置 → 跳过）

### Changed
- 中间过程表的「⏭️ 跳过」子原因从 2 种扩为 4 种（已覆盖 / 非用户可操作 / 本机不可用 / 不可感知），第六步摘要要求按子原因分列条数

- frontmatter `description` 补充「按环境可用性与可感知性双重门禁新增条目」，使触发时即可见双门禁定位

### Notes
- 本次配套的数据侧清理（tips.jsonl 280 → 263 条，删除 17 条无验证闭环条目）属人工发起的一次性维护，不由本 skill 自动执行；🗑️ 删除条件已明确「存量库中未被本轮 changelog 触及的不可感知条目不在自动删除范围内」，避免 skill 自行扫库删除
- CHANGELOG 缺失 1.4.0 / 1.5.0 两版记录（SKILL.md 已到 1.5.0），本次不代为补写，留待相应改动的作者补记

## [1.3.0] - 2026-09-04

### Changed
- **存储格式从 `tips.txt` 迁移为 `tips.jsonl`**：每行一个 JSON 对象 `{id, category, title, body}`，`id` 为稳定主键（命令/参数/功能名），`body` 内用真实换行。原格式靠 `---` 分隔行 + 字面量 `\n` 拼接字段，判重需正则提取、计数需数分隔符，两者都易错；JSONL 下判重是查 `id` 集合、计数是数行数
- 第二步判重从「grep 正则提取标识符」改为「读 JSONL 构建 `ids` 与 `aliases` 两个集合」，新增 `norm_alias()` 归一化：去斜杠前缀、`-`→`_`、统一小写，使 `/code-review`≡`code-review`≡`code_review`、`--flag`≡`flag` 能命中同一键
- 第四步写入方式改为行级操作：新增=追加一行 JSON、修改=整行替换、删除=移除该行，不再需要处理 `---` 分隔符的成对增删
- 第五步条目计数从「数 `^\[` 开头行」改为「数 JSON 行」（`grep -c '^{'` 与 `wc -l` 交叉验证）

### Added
- **新增 `scripts/` 目录**，把第二步的两个内联 Python 块抽为可测脚本，配 46 个 unittest（本机无 pytest，与仓库另两个维护型 skill 一致）：
  - `build_alias_index.py` — 读 tips.jsonl 构建 `{ids, aliases}` 标识符集，输出 JSON
  - `detect_residue.py` — 库内残影召回，输出待人工裁决的候选
  - `test_build_alias_index.py` / `test_detect_residue.py` — 22 + 24 tests
- 第二步新增「辅助：库内残影检测」小节：对已有条目做主标识符分组 + 功能描述重叠召回，捕捉历次 sync 累积产生的互相覆盖冗余——此前判重是单向的（新条目 vs 已有），库内互相覆盖永远检测不到
- 第三步新增「环境可用性门」：条目须在本机 harness 下确实能跑，mac/Linux 专属、Enterprise 席位、需组织管理员权限、云厂商 SDK、claude.ai 账号会话类一律判 ⏭️ 跳过。判据是「有无硬性阻断」而非「听起来像不像企业向」——本机走自定义网关，网关类条目反而可用
- 第三步完整性校验的「完整可执行形式」从只覆盖 CLI 命令扩展为三种形态：CLI 命令、斜杠命令、skill 名（须写触发形式），并显式禁止裸缩写（不得写 `/tdd`、`debugging`、`parallel-agents` 这类敲不出来的简称）
- 第四步「修改」补充两条约束：覆盖旧语义而非在原句后追加版本沿革从句；长度自检不超过 body 中位数的 2 倍
- 第五步格式校验从「验前 4 字段前缀顺序」改为「验 `{id,category,title,body}` 四字段齐全 + 统计 body 内 `功能：`/`效果：`/`例子：` 各前缀出现次数，任一 > 1 即报错」，捕捉同一条内字段语义重复
- `known-issues.md` 新增「2026-09-04 JSONL 迁移后的实测复核」小节，用脚本复核数据层现状并与台账记录值对照

### Fixed
- **修复内联版残影检测形同不存在**：`items = []` 从未被填充，两层循环永不执行，候选恒为 0。脚本化后实测召回 5 个候选，其中 `/doctor` 那两条经人工确认是真残影（后者完整覆盖前者的别名、CLAUDE.md 裁剪、版本信息，还多出安装健康/未用 skill/慢 hook 等内容）
- **修复 aliases 集被通用英文词污染**：加固版曾用 `\b[a-z][a-zA-Z]{3,}\b` 收录正文所有 4 字母以上小写词，集合膨胀到数千个通用词（`effect`、`when`、`with`…），任何 changelog 功能点都能"命中"→ 判重恒为已覆盖、新增恒为 0。改为只收带语法标记的标识符后 aliases 从 1622 收敛到 1475，通用词清零。这是不报错的静默失效，已被 `TestExtractRejectsNoise` 锁住
- **修复文件路径被误当斜杠命令**：`.claude/settings.json` 的 `/settings`、`~/.claude` 的 `/claude`、`github.com/example/repo` 的 `/example` 均被收录为命令。斜杠命令模式加前置断言 `(?<![\w./~-])` 排除路径分量，真 flag（`--settings`）与真命令（`/cost`、`/superpowers:brainstorming`）全部保留
- **修复中文按连续片段整取导致真残影召回率为 0**：`是完整的配置体检工具` 被当成单个 token，与另一条的 `设置体检` 永不重合。改为 bigram（2-gram）切分，`/doctor` 那两条的重叠率从 0 变为可测的 0.263
- 残影检测阈值按实测分布定为 0.25 并明确「只召回不判定」定位：真残影（0.263）与非残影（`MCP-资源列出 ⊇ MCP-服务器`，0.333）在数值上交叠，纯词频无法可靠区分，最终取舍交由第四步 CHECKPOINT 由用户裁决
- **第五步同步点从 4 处补全为 6 处**：扫描正则由 `条技巧`（要求两词紧邻）放宽为 `条[^，。|]*技巧`，随即发现 `.kiro/steering/structure.md` 与 `.kiro/steering/product.md` 两处措辞为「N **条使用技巧**」——中间插了「使用」二字，旧正则永不命中，两处数字从未被任何一轮 sync 更新过，长期停在 425（真实 276）。甄别表补两行 ✅、PowerShell 循环补两个路径、兜底表与第六步摘要口径同步改为 6 处
- 甄别表 ❌ 不动项「默认每次显示 2 条技巧」更正为「6 条技巧」，与 show-tip.sh 本次的默认值变更对齐
- `test-prompts.json` 的 id 1 expected 中「同步 5 处文档数字」校正为实际处数（SKILL.md 第五步已是 4 处，仅测试素材残留旧数字）。改的是对事实的描述而非期望的行为，不属于「重写既有测试条目」
- `known-issues.md` 7 条「待处理」标记为「已修复」（1.3.0）。剩余 1 条（分类标签是未经验证的事实断言）规则未加固，如实保留待处理

### Notes
- 本次 SKILL.md 属 `.claude/` 下改动，不触发仓库 marketplace 版本升级
- 同批次的 `plugins/optimus-devops-plugin/hooks/` 改动另按仓库规则升版：show-tip.sh 读 JSONL + 默认显示条数 2→6（Patch）、**删除 `install.ps1`**（删除用户可见功能 → Major）。install.sh 已完全覆盖其能力且内置 Windows 下的 BurntToast 检测，唯一差异是 ps1 曾提供交互式 `Install-Module`，现改为打印命令由用户自行执行——交互式安装不适合放在安装脚本里，跨 shell 传 stdin 也不可靠
