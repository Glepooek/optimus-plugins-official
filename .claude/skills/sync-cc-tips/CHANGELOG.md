## [2.2.0] - 2026-09-09

功能性重构：**保持流程行为不变，把正文内嵌的机械执行步骤全部下沉到 `scripts/`**。SKILL.md 561 → 535 行，新增 3 个脚本与 103 个单测（51 → 154 tests）。

重构的判据是**分离「判断」与「执行」**：判定规则（可感知性门、三类差异条件、斜杠名四种处置、长度自检矩阵）模型必须读懂才能判断，一字未改留在正文；机械执行步骤（curl 降级链、JSON 校验、二进制 grep）由脚本接管并被单测锁住。

**最大收益不在删代码块，而在删警告。** 原第一步有 3 段黄字警告（`curl … | awk …` 吞退出码、`github.com/…/raw/…` 302 回落、不要加同主机重试），存在的唯一理由是模型每轮都要手写那条 curl。正确写法固化进脚本 + 单测后，这些警告的约束对象从「不要这样写命令」变为「不要这样改脚本」，三条合并为一条且防错强度从「叮嘱」升为「锁死」。

### Added
- **`scripts/fetch_changelog.py`**（37 tests）：读锚点 → urllib 两跳取数（`raw.githubusercontent.com` → `api.github.com`，**换主机名而非换工具**）→ 按锚点截断 → 失败时连通性分诊。输出 `{ok, hop, versions, range, needs_confirm, advance_anchor, verdict, next}`。退出码 0/3/4/2 区分成功、两跳皆败、解析失败、参数非法。`TestHopsAreIndependent` 断言各跳主机互不相同、不指向会重定向的 URL、api 跳带 `Accept: application/vnd.github.raw`——防止再退回「换工具不换主机」
- **`scripts/validate_tips.py`**（36 tests）：九项检查一次跑完（`line_count`/`json_valid`/`schema`/`id_unique`/`field_dup`/`body_shape`/`length`/`orphan_ref`/`count_match`），合并原第三步格式校验与第五步四重校验为单一调用点。`TestFieldDup` 锁住「例子不参与重复计数」这条最易写错的规则
- **`scripts/check_slash_name.py`**（24 tests）：分块扫描二进制点查斜杠名，`verdict` 四取值与原表四行处置一一对应。**只取证不下结论**——输出 `evidence[].context` 原文与 `registry_markers`，注册体判断留给读到证据的人
- **第二步新增改动前基线体检**：跑 `validate_tips.py` 记下 `entries` 与既有 `failed` 项，避免把存量缺陷误算成本轮写入错误。三个第二步脚本的失败处置刻意不同（判重集失败必停、残影检测失败不中止、基线体检失败交用户裁决），正文明确标注「不要照搬」
