# 取证台账

本文件收录 SKILL.md 中各条判据、阈值、禁令背后的**一次性实测数据与历史观测**。

**何时加载**：仅在两种场景——① 有人质疑某条判据或阈值的取值依据；② 打算改动某个阈值、开关或禁令。正常执行 sync 流程**不需要读本文件**，判据本身已完整写在 SKILL.md 正文。

⚠️ **本文件的数值不跟改。** 每条都标注了观测日期与当时的样本量，它们是**当次实验的记录**，不是当前库状态。库存变了不要来同步这里的数字——跟改即伪造实验记录，会让「按什么依据定的」永久失去可核查性。需要当前值一律现跑脚本。

⚠️ **本文件不是缺陷台账。** 真实使用中暴露的问题及其修复记录在 `known-issues.md`，两者职能不同：那里是「哪里坏了、怎么修的」，这里是「判据从哪来的」。

## 阈值取值

### 残影召回阈值 0.25（`detect_residue.py`）

2026-09-04 在当时 **276 条**库上实测：

| 组合 | 重叠度 | 人工判定 |
|---|---|---|
| `/doctor` 两条（互为详略版本） | **0.263** | 真残影 |
| `MCP-资源列出 ⊇ MCP-服务器` | **0.333** | 非残影 |

两类在数值上**交叠**——真残影的分数低于非残影，纯词频无法可靠区分。故阈值按**召回**定为 0.25，宁可多召回几个交人裁决，而不是追求精确率。

这是 `detect_residue.py` 输出为「待裁决候选」而非「判定结果」的根据：脚本在原理上做不到自行判定，所以设计上也不允许它删。

### 条目长度自检只查本轮改动条目

2026-09-09 实测 **268 条**库中 **20 条**超长度阈值（7.5%），其中 **18 条**属本轮未触及的存量。按全库状态执行会每轮被无关存量卡住，故该检查只覆盖本轮新增与修改的条目。

## 已证伪的写法

以下每条都实际写过并失效，对应 SKILL.md 黑名单中的一行禁令。列在此处是为了让禁令**可核查**——否则读者只能选择相信。

### 手工 grep 判重（集合膨胀）

曾用 `\b[a-z][a-zA-Z]{3,}\b` 收录裸英文词，别名集合膨胀到**数千个通用词**，导致任何功能点都能「命中」→ 判重恒为已覆盖、新增恒为 0。属**不报错的静默失效**：流程每轮都跑通，产出恒为空。

现由 `test_build_alias_index.py::TestExtractRejectsNoise` 锁住。

### `fetch_changelog.py` 降级链的三种伪冗余

| 写法 | 为什么无效 |
|---|---|
| `curl … \| awk …` | 管道吞掉 curl 退出码，降级链永不启动 |
| `github.com/<repo>/raw/…` 当第二跳 | 302 回落 raw 域；字节等价对**内容**成立、对**可达性**不成立。`--max-redirs 0` / `-f` 对 302 仍返 `exit 0` |
| 等 N 秒重试同一条命令 | 同主机同工具，故障域与首跳完全重合 |

三者的完整实测数据在 `known-issues.md`。结论：**新增跳必须换主机名**，不是换工具、不是换 URL 字符串。现由 `test_fetch_changelog.py::TestHopsAreIndependent` 锁住。

### 把 `not_found` 当否证

`check_slash_name.py` 对**随附 skill** 一律报 `not_found`，因为它们是惰性解包的内嵌资源，名字不以 `name:"x"` 字面量存在于可执行段。`/simplify`、`/dataviz`、`/deep-research` 三条全部实测可用而脚本一律报 `not_found`，三条都曾据此被错误提请删除或写成「没有斜杠命令」，均被用户实跑推翻。详见 `known-issues.md`。

### 派生数字写死在文案里

曾有 **6 处**同步点把 tips 条目总数冗余写进展示文案，每轮 sync 手工追平。实际结果：漏了两轮，其中**两处长期停在 425**（当时真实值 276）。2.0.0 版为此废除整套「同步文档数字」机制，6 处同步点归零。

### 改流程漏改 `test-prompts.json`

两次流程改动分别产生失效断言：废除「同步文档数字」牵连 id 1/3/4；把内嵌命令抽成三个脚本牵连 id 2/6/7/10/12。删除或重命名步骤会让指向该步骤的 `expected` 变成**恒定失败**的断言，抽脚本会让断言了具体命令写法的 `expected` 失效。

### 别名归一化覆盖不到语义等价

`SEMANTIC_ALIASES` 里的 4 组（`/cost`≡`/usage`≡`/stats`、`/review`≡`/code-review`、`/plugin`≡`/plugins`、`/undo`≡`/rewind`）是历史重复条目的直接产物——字面归一化（前缀剥离、连字符下划线互换、小写）对字面无关的等价名无效，只能显式登记。
