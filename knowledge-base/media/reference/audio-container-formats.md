# 音频封装格式：文件后缀与真实编码的辨析

## 1. 音频文件的构成

音频文件和视频文件一样是"容器 + 编码"两层。但音频场景的特殊性在于：**很多音频格式把容器和编码绑得很紧**，后缀往往同时暗示了编码，容易造成混淆。

需要先建立的三个认知：

1. `.wav` 是**容器**（RIFF），里面默认装未压缩的 PCM——但 WAV 也可以装压缩编码
2. `.mp3` 是**编码**（MPEG-1 Audio Layer III），严格说没有专属容器，通常裸存或放进 MPEG 容器
3. `.flac` 既是编码也是封装——FLAC 是一套完整的"编码 + 容器"方案，所以后缀直接等于编码

## 2. 常见音频格式辨析

| 后缀 | 本质 | 容器 / 编码 | 压缩 | 典型用途 |
|---|---|---|---|---|
| `.wav` | 容器（RIFF） | RIFF 容器 + PCM（默认） | 未压缩（无损） | 录音、剪辑中间文件、系统提示音 |
| `.aiff` | 容器 | Apple 版 RIFF + PCM | 未压缩（无损） | Apple 生态录音/剪辑 |
| `.flac` | 编码 + 封装一体 | FLAC | 无损压缩 | 无损音乐存档、高品质播放 |
| `.alac` | 编码（装进 MP4） | MP4 / CAF 容器 + ALAC | 无损压缩 | Apple 无损音乐 |
| `.mp3` | 编码 | MPEG 容器 / 裸流 | 有损 | 通用音乐、老设备、播客 |
| `.aac` | 编码 | 裸 AAC 流 | 有损 | 广播、Apple 音乐 |
| `.m4a` | 容器 | MP4 容器 + AAC（或 ALAC） | 有损（或无损） | Apple 生态音频；MP4 的"纯音频扩展名" |
| `.ogg` | 容器 | Ogg 容器 + Vorbis / Opus | 有损 | 开源生态、游戏、网页 |
| `.opus` | 编码 | Ogg / WebM / TS 容器 + Opus | 有损 | 语音、低码率高质场景（VoIP、直播） |
| `.mka` | 容器 | Matroska 容器（音频专用） | 任意 | 把任意编码装进 MKV 只留音频 |
| `.wma` | 编码 / 容器 | 微软 ASF 容器 + WMA 编码 | 有损/无损 | Windows 老生态 |

## 3. "后缀 vs 编码"的判断方法

后缀只给**线索**，不一定是真相：同一个 `.m4a` 里面可能是 AAC（有损）也可能是 ALAC（无损）；`.wav` 里默认 PCM 但也可能装着别的。确认真实编码的唯一可靠方式是读元数据：

- 用 ffprobe 查看音频流的 `codec_name` 字段（实操见 `ffprobe-field-map.md`）
- 辅证判断：未压缩的 PCM 码率 ≈ 采样率 × 位深 × 声道数（公式见 `audio-parameters.md`），明显低于该值的通常是有损压缩

## 4. 常见误区

- **"WAV 一定无损"**：WAV 只是容器，装 PCM 才无损；装压缩编码的 WAV 同样有损
- **"FLAC 体积大所以音质更好"**：无损格式保留全部原始数据，体积大是"信息完整"的结果而非音质好坏的直接度量；无损可逆、有损不可逆，这才是关键差别
- **"把 MP3 转成 FLAC 音质就变好了"**：转码不能无中生有。有损转无损只是把已丢失的信息重新"包裹"，音质停留在原 MP3 的水平（有损/无损概念见 `video-quality.md`，同样适用于音频）
