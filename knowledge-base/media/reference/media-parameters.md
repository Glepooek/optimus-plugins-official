# 媒体参数：分辨率、帧率、码率及其关系

## 1. 分辨率（Resolution）

分辨率指图像的像素尺寸，写作"宽 × 高"（如 1920×1080）。档位通常以**垂直像素数**命名。

常见档位：

| 名称 | 像素（宽×高） | 宽高比 | 备注 |
|---|---|---|---|
| 480p / SD | 720×480（或 640×480） | 4:3 或 16:9 | 标准清晰度，DVD 时代 |
| 720p / HD | 1280×720 | 16:9 | 入门高清 |
| 1080p / Full HD | 1920×1080 | 16:9 | 最主流高清：电视、蓝光、网页 |
| 1440p / QHD | 2560×1440 | 16:9 | 显示器、手机 |
| 2160p / 4K / UHD | 3840×2160 | 16:9 | 超高清：现代电视、流媒体 |
| 4320p / 8K | 7680×4320 | 16:9 | 顶级超高清 |

> 注意：`2K` 一词有歧义——影院标准 2K 指 2048×1080，消费级语境有时用它指 2560×1440（更规范的叫法是 QHD）。读到 2K 时按上下文判断。

相关概念：

- **宽高比（Aspect Ratio）**：宽与高的比例。拉伸、裁切会改变宽高比，转码时注意保持或明确意图
- **有效分辨率**：某些源视频上下带黑边（letterbox），黑边算入分辨率但不含画面信息，裁剪后的才是"有效"画面

#### 常用视频比例

| 比例 | 方向 | 典型场景 |
|---|---|---|
| 16:9 | 横屏 | 现代电视/视频/网页的标准比例 |
| 4:3 | 横屏 | 老电视、监视器、早期视频 |
| 21:9 | 横屏 | 影院超宽银幕（宽银幕电影） |
| 9:16 | 竖屏 | 竖屏短视频（抖音/快手/Reels/Shorts） |
| 1:1 | 方形 | 社交平台信息流视频 |

#### 横屏 vs 竖屏如何区分

方向由宽高比决定：**宽 > 高为横屏（landscape），高 > 宽为竖屏（portrait）**。

- 判断方法：比较 `width` 与 `height`——`width > height` 即横屏，`height > width` 即竖屏；ffprobe 的宽高字段可直接判断
- 常见比例：横屏多为 16:9 / 4:3 / 21:9，竖屏为 9:16
- 转码注意：竖屏素材转横屏（或反之）直接拉伸会变形，正确做法是裁切（crop）或加黑边（pad）；分辨率的宽高数字不携带方向语义，方向完全由两者大小关系决定

## 2. 帧率（Frame Rate）

帧率指每秒播放的画面数，单位 fps。帧率影响流畅度与运动清晰度。

常见帧率：

| 帧率 | 场景 |
|---|---|
| 23.976 / 24 fps | 电影（影院标准） |
| 25 fps | PAL 制电视（欧洲/中国广播电视） |
| 29.97 / 30 fps | NTSC 制电视（北美/日本）、网络视频 |
| 50 / 60 fps | 直播体育、游戏录制、高帧率视频 |
| 120 fps | 高端游戏、慢动作 |

相关概念：

- **恒定帧率 CFR**：每帧间隔相同，播放稳定，常规文件标准
- **可变帧率 VFR**：帧间隔可变（屏幕录制、混合来源素材常见），帧间时长不均
- 帧率不是越高越好：>24 fps 视觉已"连续"，60/120 fps 的动作清晰度与流畅度更高，但高帧率意味着更多数据要编码、文件更大
- **提高帧率的两种方式**：
  - **复制帧（dup）**：机械复制已有帧凑数，帧率数字变了，但画面运动感与原始一致，不真正增加流畅度
  - **运动插帧（motion interpolation）**：分析相邻帧的运动矢量生成中间帧，真正提升流畅度，但计算量可达简单复制的数倍到数十倍，且高速运动、遮挡、场景切换处易产生插值伪影
- **降低帧率 = 均匀丢帧（drop）**：抽走多余帧，无画质损失

## 3. 码率（Bitrate）

码率指单位时间内传输/存储的比特数，单位 kbps / Mbps。码率决定体积与画质/音质的权衡：码率越高，保留细节越多、体积越大。

#### 单位与进制换算

码率单位链是 bps → kbps → Mbps → Gbps，**相邻进率为 1000（十进制）**——这是视频/网络领域惯例，与存储容量的 1024（二进制）不同：

| 单位 | 换算 | 示例 |
|---|---|---|
| bps | 基本单位 | ffprobe 的 `bit_rate` 字段直接输出 bps |
| kbps | 1 kbps = 1000 bps | 192 kbps 音频 = 192000 bps |
| Mbps | 1 Mbps = 1000 kbps | 8 Mbps 视频 = 8000 kbps |

换算示例：ffprobe 输出 `bit_rate = 8154340`（bps）→ 除以 1000 两次得 8.154 Mbps。注意文件大小的字节单位（KB/MB/GB）按存储惯例是 1024 进制，两者不要混用：**码率用 1000，文件大小用 1024**。

> 常见坑：把 Mbps 当成 MB/s。码率 8 Mbps 是每秒 8 兆**比特**，换算成每秒**字节**是 8 ÷ 8 = 1 MB/s（1 字节 = 8 比特）。

- **视频码率 vs 音频码率**：一条视频流和一条音频流各有码率，文件总码率是两者（及字幕等）之和
- **CBR（恒定码率）**：整段固定码率，体积可预测，但低复杂度画面浪费带宽
- **VBR（可变码率）**：按内容复杂度动态分配，画质一致性好、整体更省体积，主流选择
- **ABR（平均码率）**：目标平均码率，介于两者之间，适合流媒体限流场景

## 4. 三者关系与码率估算

三个参数共同决定"每一秒要编码多少画面信息"：

```
像素吞吐量 = 分辨率（宽 × 高） × 帧率
码率       ≈ 像素吞吐量 × 压缩因子 ÷ 编码效率
```

- 分辨率与帧率不变时：码率越高画质越好（有损编码下）
- 编码效率不变时：分辨率或帧率翻倍，维持同画质所需码率大致翻倍
- 实际压缩比由编码器、内容复杂度与质量目标共同决定（见 `video-quality.md` 的 CRF / 2-pass）

#### 由目标体积反推目标码率（two-pass 场景）

反过来，若要求"压缩到指定大小"，可反推目标码率：

```
目标视频码率(kbps) ≈ 目标大小(MB) × 8192 / 总时长(秒) − 音频码率(kbps)
```

- `8192 = 1024 × 8`：目标大小按存储 1024 进制换算为 KB，再 ×8 把字节换算为比特——正是上文"文件大小用 1024、码率用 1000"分界点的落地；分子得到的是**总码率**（含音频），需减去音频码率（如 128 kbps）才是视频码率
- 这是 **two-pass（`-b:v`）模式**的输入：按该码率两轮编码精确逼近目标体积，体积可控但画质随内容复杂度波动（与 CRF 的取舍见 `video-quality.md` §2）
- 与 CRF 模式的分工：**CRF 只定质量不定体积**；只有对文件大小有硬性要求时才用目标码率模式，两者互斥

常见参考（H.264 下 1080p 视频的通用档位，仅供参考，视内容而定）：

| 场景 | 1080p 参考码率 |
|---|---|
| 网页低清 | 2–3 Mbps |
| 网络视频通用 | 5–8 Mbps |
| 高清保存 / 蓝光级 | 10–20 Mbps |

> 这些是经验值。同码率下，内容简单（静止画面/对话）画质好，内容复杂（剧烈运动/噪点）画质差——这正是 VBR / CRF 存在的原因。

## 5. 常见误区

- **"4K 一定比 1080p 清晰"**：分辨率只决定像素量，清晰度还取决于码率、编码器与片源质量；低码率 4K 可能比高码率 1080p 更糊
- **"60fps 一定比 30fps 好"**：对运动场景是，对电影感素材未必；高帧率文件更大、编码更慢
- **"码率越高越好"**：超过人眼可感知阈值后，继续提码率只增体积不增观感；合理做法是按目标场景选择够用的码率
