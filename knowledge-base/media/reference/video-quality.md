# 视频质量：有损 / 无损、码率控制、色度采样、位深与 HDR

## 1. 有损 vs 无损

- **有损编码**（绝大多数视频编码）：丢弃人眼不敏感的信息，体积大幅下降，不可逆
- **无损编码**：保留全部原始信息，体积巨大，仅特定场景使用（如无损剪辑中间、屏幕录制存档）
- **关键认知**：有损转无损**不恢复信息**。把 H.264 重编码成"无损"只是把已丢失的信息重新包裹，画质停留在有损源水平；无损 → 有损则不可逆

## 2. 码率控制模式

| 模式 | 机制 | 特点 | 适用 |
|---|---|---|---|
| CBR | 全程固定码率 | 体积可预测，画质波动大 | 直播 / 流媒体带宽受限 |
| VBR | 按复杂度分配 | 画质一致，体积更省 | 本地文件、存档 |
| CRF / 质量档 | 按**感知质量**目标编码 | 只定质量不定码率，最简单高效 | 绝大多数转码场景 |

- **CRF（恒定质量）**：x264 / x265 / AV1 都支持。给定质量档（x264 常见 18–28，**数值越低质量越高**），编码器自动决定每帧码率，输出体积不确定
- **2-pass VBR**：第一遍分析内容，第二遍精确分配码率。适合"必须控制在某码率/体积内"的交付场景，比单遍 VBR 质量稳定

## 3. 色度采样（Chroma Subsampling）

人眼对亮度比对颜色敏感，视频编码因此对色度降低采样。记法 `4:4:4 / 4:2:2 / 4:2:0` 表示色度信息保留比例：

| 采样 | 色度保留 | 典型用途 |
|---|---|---|
| 4:4:4 | 完整 | 专业调色、字幕合成、CG 中间件 |
| 4:2:2 | 一半 | 广播级制作、摄影机记录 |
| 4:2:0 | 四分之一 | 消费级分发（网页、蓝光、手机） |

- 消费级视频几乎都是 **4:2:0**，蓝光、流媒体、电视全是
- 转码时把 4:2:2 / 4:4:4 的源降到 4:2:0 会永久丢失色度细节，专业工作流需注意

## 4. 位深（视频）

视频位深指每色通道用多少比特表示，决定色彩渐变的平滑度（防色带 banding）：

- **8-bit**：256 级/通道，消费级主流
- **10-bit**：1024 级/通道，**HDR 的硬性要求**；现代 HEVC/AV1 高质量 SDR 也常用
- **12-bit**：专业 / 高端 HDR

低码率 + 8-bit 在渐变画面（天空、暗部）容易出现可辨识色带，10-bit 显著缓解。

## 5. HDR（高动态范围）

HDR 通过**宽色域 + 高亮度**扩展画面动态范围，与 SDR 相对：

| 标准 | 元数据 | 典型用途 |
|---|---|---|
| SDR（Rec.709） | — | 传统标准，绝大多数现存内容 |
| HDR10 | 静态元数据（整片一个亮度上限） | 最普及的 HDR：蓝光、流媒体、电视 |
| HDR10+ | 动态元数据（逐场景） | 三星系设备、部分流媒体 |
| HLG | 向后兼容 SDR 广播 | 电视广播、直播 |
| Dolby Vision | 动态元数据 + 强兼容分层 | 高端蓝光、Apple / Netflix 流媒体 |

- **转码最大陷阱**：HDR 片源转码时若丢失 HDR 元数据或把 10-bit 降到 8-bit，画面会**发灰 / 偏色**（HDR 数据按 SDR 显示）
- 判断一个视频是否 HDR、什么标准，看 ffprobe 的 `color_transfer` / `color_primaries` 字段（见 `ffprobe-field-map.md`）

## 6. LUT（Look-Up Table，查找表）

LUT 是一张"输入颜色值 → 输出颜色值"的映射表：给定一个颜色，查表得到另一个颜色，整段视频的颜色因此被整体变换。它常用于**色彩校正与风格化**——把一种色彩空间的画面转换成另一种、套用特定的调色风格（如电影感、胶片模拟），是专业调色工作流的核心工具。

两种主要类型：

| 类型 | 机制 | 特点 |
|---|---|---|
| 1D LUT | 每个通道（R/G/B）独立查表 | 只处理单通道色阶，用于白平衡、对比度、灰阶校正；无法实现通道间交叉的复杂色彩变换 |
| 3D LUT | 以 (R,G,B) 为坐标的三维查表 | 可表达任意色彩变换（饱和度、肤色偏移、色相混合等），是调色风格 LUT 的主流形态 |

常见文件格式：`.cube`（Adobe / 行业通用）、`.3dl`、`.look`（DaVinci Resolve）等。

**LUT 与 HDR 的关系**：HDR/SDR 转换常借助 LUT 完成。例如 HDR → SDR 的色调映射（tone mapping）把宽色域、高动态的 HDR 信号压缩映射到 SDR 范围，既有算法实现也有预设转换 LUT；反过来给 SDR 素材套用 HDR 显示转换 LUT 可模拟 HDR 观感。

**注意点**：

- LUT 只做颜色变换，不改变分辨率、不重编码；它在解码后、编码前的色彩处理环节生效
- 无法从文件元数据判断某段视频是否套过 LUT——LUT 是**处理时**应用的工具，不是文件内数据；转换后效果已"烧进"像素，原始 LUT 需另行保留
- 消费级播放几乎不接触 LUT，它是制作/调色环节的概念

## 7. 保画质转码要点

1. 能**流复制**就不转码（见 `media-stream-basics.md`）
2. 必须转码时优先 **CRF 恒定质量**而非固定码率
3. 原片是 HDR 时：保住 10-bit 位深与 HDR 元数据，不要降成 SDR 8-bit（除非明确要转 SDR）
4. 原片是 4:2:2 / 4:4:4 且需要专业用途时，不要降采样到 4:2:0
