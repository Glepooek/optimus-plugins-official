# 媒体流结构基础：容器、流、转码 / 重封装 / 流复制

## 1. 一个媒体文件由什么构成

一个媒体文件（如 `movie.mkv`）在结构上由两层构成：

1. **容器（Container / Mux）**：外层"盒子"，负责把若干条流打包在一起，并记录时长、元数据、章节等附加信息
2. **流（Stream）**：内层被编码的数据，通常包括：
   - **视频流**：一段经过编码的画面（如 H.264）
   - **音频流**：一段经过编码的声音，可以有**多条**（不同语言、不同声道）
   - **字幕流**：一条文本或图形字幕，可有可无，也可以多条
   - 其他：章节（chapters）、附注数据（attachment）

> 关键认知：**扩展名 ≠ 编码**。`movie.mp4` 只说明外层是 MP4 容器，里面的视频流可能是 H.264，也可能是 H.265 或 AV1。容器与编码是正交的两个维度。

## 2. 容器与流的职责分工

| 层 | 职责 | 例子 |
|---|---|---|
| 容器 | 复用（Muxing）：把多条流按时间交错装进一个文件；提供索引、元数据、章节 | MP4、MKV、AVI、TS |
| 流 | 编码：把原始画面/声音压缩成可存储、可传输的数据 | H.264、HEVC、AAC、FLAC |

容器不关心流的编码细节，流也不关心自己被装进哪个容器——但**并非所有"容器 × 编码"组合都合法**：容器对能容纳的编码、音频/字幕流数量有各自限制（如 MP4 对图形字幕支持差、MKV 几乎什么都能装）。组合兼容性在 `video-container-formats.md` 中展开。

## 3. 转码、重封装、流复制

处理媒体文件的三个核心操作，对应"动容器"与"动编码"两个自由度的不同组合：

| 操作 | 改变容器 | 改变编码 | 代价 | 典型场景 |
|---|---|---|---|---|
| 转码 Transcode | 是 | 是 | 重新编码，耗时、画质有损（除非无损重编码） | 换编码（如 H.264→AV1）、调整分辨率/码率/帧率 |
| 重封装 Remux | 是 | 否 | 只搬运流，快、无画质损失 | 换容器（如 MKV→MP4）、改封装不改内容 |
| 流复制 Stream Copy | 否（或部分） | 否 | 只复制所选流，快、无画质损失 | 抽取某条音轨/字幕流、删除多余流 |

- **转码** = 解码 → 重新编码。容器变了，流也重编码了。缩放、改帧率、压缩码率都属于转码。
- **重封装** = 只换容器。容器变了，流原封不动——之所以快，是因为只重新打包，不碰编码数据。
- **流复制** = 从原文件复制所选流到新文件。可以在同一容器内删掉不要的流（如去掉多余音轨），也可以把选中的流搬进另一个容器。跨容器流复制仍受目标容器的流支持限制。

### 3.1 如何在命令行区分

ffmpeg 中 `-c copy`（stream copy）表示"不重编码，直接复制流"；省略或指定具体编码器（如 `-c:v libx264`）则是转码。判断自己处于哪种操作，看有没有指定编码器即可。

## 4. 为什么理解流结构很重要

- **分析时**（media-analyze）：要逐流看——视频流的分辨率/帧率/编码、各音频流的语言/编码/声道、字幕流是否存在，而不是只看"一个文件"
- **转换时**（media-convert）：选哪条流转码、哪条流复制、字幕是否保留，都需要先知道文件里有哪些流
- **播放/兼容性判断**（media-play）：目标播放器能解码什么编码、支持什么容器，决定文件能不能正常播放

## 5. 一条流的关键属性

无论视频还是音频流，判断"这条流是什么、怎么样"看这几类属性（字段映射见 `ffprobe-field-map.md`）：

| 属性类别 | 视频流 | 音频流 |
|---|---|---|
| 编码 | codec（H.264 / HEVC / AV1…） | codec（AAC / MP3 / FLAC…） |
| 参数 | 分辨率、帧率、码率、色度采样、位深 | 采样率、位深、声道数、码率 |
| 元数据 | 语言、标题、时间轴基准 | 语言、标题、声道布局 |

各属性的概念解释分别在 `media-parameters.md`、`audio-parameters.md`、`video-quality.md` 中展开。
