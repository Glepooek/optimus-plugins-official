# 02 · 项目结构与布局

> 更新历史：2026-08-21 创建。目录 / 资源 / 命名约定与 `wpf-project-conventions` skill 互为事实来源，本文件是原则侧。

WPF 项目的目录结构、文件职责与资源组织方式。生成工具（mastergo 系列）产出的文件必须落在本布局内。

## 1. 解决方案布局

标准布局，新仓库必须遵守，存量仓库逐步收敛：

```
<repo>/
├── src/
│   └── <Company>.<Product>.App/          # WPF 可执行项目
│   ├── App.xaml                          # 应用级入口 + 资源字典合并
│   ├── Views/                            # 窗口与页面（View）
│   ├── ViewModels/                       # 视图模型
│   ├── Models/                           # 数据模型 / DTO
│   ├── Services/                         # 业务服务
│   ├── Controls/                         # 自定义控件 / 用户控件
│   ├── Themes/                           # 样式、主题、资源字典
│   │   ├── Colors.xaml
│   │   ├── Styles.xaml
│   │   ├── DataTemplates.xaml
│   │   └── Converters.xaml
│   └── Converters/                       # IValueConverter（或并入 Themes/Converters.xaml）
├── tests/
│   └── <Company>.<Product>.App.Tests/
├── Directory.Build.props
└── <Product>.sln
```

- **必须**：View / ViewModel 分层目录清晰，`Views` 与 `ViewModels` 一一对应（`LoginView.xaml` ↔ `LoginViewModel.cs`）
- **必须**：`Themes/` 集中资源字典，`App.xaml` 只做合并与引用，不在 App.xaml 内堆叠内联样式
- **应该**：Converter 独立成文件或在 `Themes/Converters.xaml` 统一注册，不散落在各 View 的局部资源
- **禁止**：仓库根目录放置业务代码；根目录只放解决方案级文件与文档

## 2. App.xaml 职责与资源字典合并

- **必须**：`App.xaml` 是应用组合根——声明 `StartupUri` 或接管 `OnStartup` 做 DI 容器初始化与导航启动
- **必须**：合并的资源字典登记进清单（与 `wpf-project-conventions` skill 第 4 节一致），新增资源字典必须同步登记，否则编译验证失败
- **应该**：资源字典按职责拆分（Colors / Styles / DataTemplates / Converters 各自成册），不建一个巨型字典
- **禁止**：资源字典命名含空格、`/` 等非法字符（`x:Key` 与字典文件名都受限，联动 `07` 章）

## 3. csproj 关键配置

| 配置 | 取值 | 说明 |
|---|---|---|
| `UseWPF` | `true` | 启用 WPF 引用与 XAML 编译（见 `01` 章第 3 节） |
| `<AssemblyTitle>` | 产品名 | 窗口标题、任务栏显示名来源 |
| `<ApplicationIcon>` | `.ico` 路径 | 应用图标；缺失时系统默认图标 |
| `<ApplicationManifest>` | 可选 | DPI 声明（`PerMonitorV2`，见 `08` 章）与高 DPI 设置 |
| `<PublishSingleFile>` | 可选 | 单文件发布（见 `15` 章） |
| `LangVersion` | 不固定 | 跟随目标框架默认值，经评审后调整 |

- **必须**：`UseWPF` 为 `true`，XAML 作为 `Page` 编译为 BAML
- **应该**：可执行项目不承载业务逻辑，仅做组合根、资源与启动装配（业务在类库）
- **禁止**：同一 csproj 混编 WPF 与其他 UI 框架引用，除非必要（WinForms 互操作走 `WindowsFormsHost`）

## 4. View 与 code-behind 职责

- **必须**：View（`.xaml` + 同名 `.xaml.cs`）职责：布局、绑定、事件转命令；**不承载业务逻辑**
- **必须**：code-behind 仅保留：`InitializeComponent()`、事件处理器（并转调 ViewModel 命令或方法）、纯 UI 逻辑（聚焦、动画、窗口行为）
- **禁止**：code-behind 直接操作数据、访问数据库、调用业务服务（经 ViewModel 转发）
- **应该**：事件处理器极薄——一行转调命令即可；复杂交互逻辑移到 ViewModel 或附加行为

```csharp
// ❌ code-behind 承载业务逻辑：直接访问数据库、数据操作进 View 层，无法测试
private void SaveButton_Click(object sender, RoutedEventArgs e)
{
    var order = new Order { Amount = decimal.Parse(AmountBox.Text) };
    using var db = new AppDbContext();
    db.Orders.Add(order);              // 业务/数据访问泄漏进 code-behind
    db.SaveChanges();
    MessageBox.Show("已保存");
}

// ✅ code-behind 只转调命令：一行委托，业务在 ViewModel，可测试
private void SaveButton_Click(object sender, RoutedEventArgs e)
    => (DataContext as OrderViewModel)?.SaveCommand.Execute(null);
```

## 5. 命名规范

- **必须**：View 命名 `{Name}View.xaml`（`LoginView.xaml`），ViewModel 命名 `{Name}ViewModel.cs`（`LoginViewModel.cs`），一一配对
- **必须**：资源 `x:Key` 用 PascalCase，禁止空格与 `/`（与 `wpf-project-conventions` skill 第 5 节一致）
- **必须**：控件命名（`x:Name`）用 PascalCase，UI 元素以类型名做后缀习惯（`LoginButton`、`UsernameTextBox`）
- **应该**：组件命名优先取自设计稿组件名，不做二次翻译（联动 `mastergo-to-wpf-components`）
- **禁止**：`x:Name` 使用匈牙利命名法（`btnLogin`）或缩写（`txt1`）

```xml
<!-- ❌ 匈牙利命名 + 缩写：btn/txt 前缀 + 无意义序号 -->
<Button x:Name="btnSave" />
<TextBox x:Name="txt1" />
<TextBlock x:Name="lblMsg" />

<!-- ✅ PascalCase + 类型名后缀：可读、可搜索 -->
<Button x:Name="SaveButton" />
<TextBox x:Name="UsernameTextBox" />
<TextBlock x:Name="MessageTextBlock" />
```

## 6. 生成文件落盘规则

- **必须**：生成文件一律写入 `Views/` / `Themes/` 等声明的目录，命名固定为 `*.generated.xaml`
- **必须**：生成文件头部含标记注释 `<!-- generated by ...; manual edits will be overwritten -->`，手工接管文件与生成文件分离（与 `wpf-project-conventions` skill 第 6 节一致）
- **禁止**：手工修改生成文件——如需改动用生成工具的覆盖或接管声明，不直接编辑

## 7. 可执行 / 测试项目边界

- **必须**：测试项目命名 `<被测>.Tests`，目录镜像源码结构，`<IsTestProject>true</IsTestProject>`
- **禁止**：测试项目引用无关实现项目；测试只引用被测项目及其必要依赖
- **应该**：ViewModel 与业务层不依赖 View 类型（可测性前提，联动 `11` 章）
