# GoF 23 个模式速查

> 本篇是 `rules/02`-`04` 的速查伴侣，供快速定位用。**不含代码**——模式的代码实现归 `knowledge-base/csharp/`，本篇只给意图、典型误用与现代替代。

规范条款（可用于合规判断的「必须/禁止」）在 `rules/` 下；本篇是描述性资料，不带规范语气。判断某个模式该不该引入时，读 `rules/01-pattern-selection.md` 与该模式所在的 `rules/02`-`04`。

## 怎么用这张表

三列的用法不同：

- **意图**：一句话确认「我想的是不是这个模式」
- **典型误用**：已经用了这个模式时，对照检查是否用错
- **现代替代**：引入之前先看这里——有替代项时优先用替代

「现代替代」列写「无」的模式，意味着语言特性没有覆盖它的意图，模式本身仍是当前的正确解法。

## 创建型（5 个）

| 模式 | 意图 | 典型误用 | 现代替代 |
|---|---|---|---|
| 单例 | 保证进程内实例唯一并提供统一访问点 | 为「方便全局访问」而用；持有可变业务状态；已有装配容器却仍用静态访问点 | 装配容器的单一生命周期注册 |
| 工厂方法 | 把「创建哪个具体类型」的决定移出调用方 | 只有一个产品类型；工厂只是构造的一层包装；由调用方传参指定类型 | 装配容器解析唯一实现（仅当无分派需求） |
| 抽象工厂 | 创建一族相关产品并保证族内一致 | 只有一个产品族；退化为一组互不相关的工厂方法 | 装配层的多套注册（多数「产品族」实为环境差异） |
| 建造者 | 分步构造复杂对象，构造过程与最终表示分离 | 为 3 个以内参数的对象引入；不校验必填项就能完成构造；建造者跨对象复用 | 命名参数 + 可选参数 |
| 原型 | 通过复制已有实例创建新实例 | 只做浅拷贝；拷贝结果与原对象共享可变状态 | 带值语义的不可变类型 |

## 结构型（7 个）

| 模式 | 意图 | 典型误用 | 现代替代 |
|---|---|---|---|
| 适配器 | 把已有契约转换为调用方期望的契约 | 两端契约都由本团队维护；适配器内含业务逻辑 | 无（外部契约不可改时它就是正解） |
| 装饰器 | 不改变契约地动态叠加行为 | 装饰链超 3 层；改变了被装饰者的语义；只有一个装饰器且无叠加计划 | 框架级拦截机制（视关注点而定） |
| 外观 | 为子系统提供简化的统一入口 | 转发数十个无关方法成为上帝对象；只封装单个组件 | 无 |
| 代理 | 提供替身并在访问前后插入控制逻辑，对调用方透明 | 契约与被代理者不一致；暴露获取真实对象的入口 | 语言/框架的惰性加载机制（仅延迟加载场景） |
| 组合 | 让单个对象与对象组合具有一致契约 | 树深度恒为 1；不需递归遍历 | 无 |
| 桥接 | 让抽象与实现两个维度独立变化 | 实现维度只有一个取值，退化为多一层的继承 | 无 |
| 享元 | 通过共享细粒度对象降低内存占用 | 未经内存实测就引入；共享对象可变 | 无（但须先有度量） |

## 行为型（11 个）

| 模式 | 意图 | 典型误用 | 现代替代 |
|---|---|---|---|
| 策略 | 封装可互换的算法族，运行时可替换 | 只有一个实现；分支集合固定不变；调用方仍按策略类型做后续分支 | 委托 / lambda（单方法无状态时） |
| 观察者 | 状态变化自动通知多个依赖方 | 订阅未配对取消；手写主题与观察者列表；依赖未定义的通知顺序 | 语言内置事件机制、响应式序列 |
| 命令 | 把操作封装为对象，使其可传递/排队/撤销/记录 | 无撤销无排队需求却套命令对象；命令持有调用上下文无法脱离原处执行 | 委托（无对象化需求时） |
| 模板方法 | 基类型定义算法骨架，可变步骤延迟到派生类型 | 钩子方法过多；派生类型覆盖骨架本身；只有一个派生类型 | 策略（可变点多于 3 个时） |
| 责任链 | 多个处理者依次尝试处理，由处理者自决 | 末端无人处理时静默返回；顺序隐式依赖注册次序 | 无 |
| 状态 | 行为随内部状态改变，状态行为分散到状态类型 | 状态类型之间直接跳转导致迁移图不可读；状态数少于 3 个 | 枚举 + 条件判断（状态少且迁移简单时） |
| 中介者 | 多对象通过中介通信，解除彼此直接引用 | 参与者少于 4 个；中介者退化为上帝对象 | 无 |
| 迭代器 | 顺序访问聚合元素而不暴露内部结构 | 手写迭代器类型 | **语言完全内置** |
| 访问者 | 不修改类型层次地新增操作 | 对封闭类型层次实现双分派结构 | 模式匹配（类型层次封闭时） |
| 备忘录 | 捕获并恢复对象状态 | 只做浅拷贝；无撤销需求却引入 | 值语义类型的快照 |
| 解释器 | 为特定语法定义解释执行的结构 | 用于固定几种表达式；自造语言而已有机制可满足 | 配置 / 已有表达式机制 |

## 按「已被替代程度」分组

引入决策时这个分组比 GoF 的三分类更有用：

| 分组 | 模式 | 处置 |
|---|---|---|
| **已被语言完全覆盖** | 迭代器 | 不再引入 |
| **多数场景被替代** | 原型、单例、访问者（封闭层次）、命令（无对象化需求）、策略（单方法无状态） | 先用替代项，替代不满足时才引入 |
| **前提严格但未被替代** | 抽象工厂、桥接、享元、组合、中介者、解释器 | 核心前提成立才引入，否则不引入 |
| **仍是常用正解** | 适配器、装饰器、外观、代理、工厂方法、建造者、观察者、模板方法、责任链、状态 | 按各自的引入信号判断 |
