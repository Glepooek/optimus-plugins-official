# 01 · 分支策略与命名规范

> 更新历史：2026-08-23 创建，迁移自 `csharp/16-collaboration.md` §1 并新增分支命名规范。

## 1. 分支策略

- **推荐**：GitHub Flow（主干开发 + 短生命特性分支），团队统一一种
- **必须**：主干（`main` / `master`）始终保持可发布状态
- **禁止**：直接在主干提交（开发走分支 + PR）
- **应该**：特性分支短命，频繁与主干同步
- **禁止**：长期大分支不合并（合并冲突地狱）

## 2. 分支命名规范

- **必须**：分支名使用 `<type>/<简短描述>` 格式，`type` 取值与提交信息 `type` 对齐（`feature`/`fix`/`release`/`hotfix`/`chore` 等），`简短描述` 用小写短横线分隔，禁止拼音或无意义占位（如 `feature/temp`）
- **应该**：分支名关联 issue/需求编号时，编号前置或后置统一约定，如 `feature/123-add-login`
- **禁止**：分支名包含个人姓名作为唯一标识（如 `zhangsan-dev`）——分支应描述做什么，不描述谁在做
- **必须**：`release/*` 分支仅用于发布前的收尾（bug fix、文案），禁止在其上开发新功能
- **应该**：`hotfix/*` 分支从主干或对应发布 tag 拉出，修复后同时合回主干与相关发布分支
