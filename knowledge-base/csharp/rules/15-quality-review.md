# 15 · 代码质量与审查

> 更新历史：2026-08-21 创建；2026-08-27 CI 门禁与 PR 流程通用条款去重，改为引用 `knowledge-base/git/`，本篇仅保留 C# 语言侧的质量约束。

质量门禁是三层漏斗：静态分析（编译期）→ 构建与测试（CI）→ 人工 review。本篇约束 **C# 语言侧**的静态分析配置、代码度量、review 内容重点与技术债务。

CI 门禁通过条件、PR 规范、合并策略、保护分支等通用协作约束见 `knowledge-base/git/rules/03-pull-requests.md`；hook 与 `--no-verify` 限制见 `knowledge-base/git/rules/02-commit-messages.md`。工具联动：`csharp-code-review` skill 辅助检出编码层面问题。

## 1. 静态分析

- **必须**：分析器告警按 warnings-as-errors 处理（联动 `01` 章第 3 节）
- **必须**：分析器规则集仓库统一；**禁止**个人全局关闭关键规则
- **禁止**：为通过构建而全局禁用分析规则（与 `01` 章一致）
- **必须**：分析器纳入 CI 门禁的构成部分（门禁通过条件本身见 `knowledge-base/git/rules/03-pull-requests.md`）

## 2. 复杂度与代码度量

- **必须**：单方法圈复杂度默认上限 20；超限需 review 拆解
- **应该**：单类超过约 400 行提示拆分（SRP，联动 `03` 章）
- **禁止**：复制粘贴代码——提取公共实现，在 DRY 与清晰度之间取平衡
- **应该**：循环嵌套深度 ≥ 3 时考虑提前返回或拆方法

## 3. Code Review 内容重点

PR 流程本身（走 PR、描述要求、批准条件）见 `knowledge-base/git/rules/03-pull-requests.md`，本节只约束 C# 代码 review 该看什么。

- **必须**：reviewer 核对审查清单（命名 / 风格 / 健壮性 / 并发 / 安全，覆盖 `02`–`14` 章对应约束）
- **应该**：用 `csharp-code-review` skill 辅助检出编码层面问题
- **禁止**：review 只点赞不复盘（形式化 review 无价值）
- **应该**：review 重心在逻辑正确性与边界，不只在风格
- **必须**：review 讨论有结论（同意 / 修改后合 / 拒绝），不留悬案

## 4. review 标准

- **阻断项（必须修复后才合并）**：逻辑错误、数据损坏、安全漏洞、性能回退、违反"必须"级规范
- **建议项（可记录后续）**：风格建议、优化机会、命名改进
- **必须**：阻断项未清不合并
- **禁止**：把建议项当阻断项拖慢节奏（破坏 review 效率与信任）

## 5. 技术债务管理

- **必须**：技术债显式登记（issue / TODO 带负责人与期限）
- **禁止**：债务无限期悬置——设定还债周期，每迭代安排
- **应该**：重构与功能并行推进，不阻塞业务交付
- **应该**：债务偿还优先高风险区（安全、并发、金额逻辑）
