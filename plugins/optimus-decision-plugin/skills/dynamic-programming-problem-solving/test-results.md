### 需要关注的薄弱点（非 FAIL，但值得记录）

- **#7 的触发依据集中在正文小节而非顶层 description**：description 的"语言信号"清单里没有任何一条覆盖"贪心算法是不是比DP更快/为什么还要用DP"这类措辞。当前能 PASS 是因为模拟评审假设 agent 会读完整篇 SKILL.md（包括 A2 的"与相邻 skill 的区分"和文末"相关 skills"声明）才做判断；但真实 Claude Code 的技能粗筛机制主要依赖顶层 `description` 字段做初步匹配，而非要求先读完全文才决定是否加载。如果生产环境的粗筛只扫 description 字符串，这条 prompt 有一定概率被判定为不够相关、未被优先加载，或被误分给 `greedy-algorithm-applicability`（如果该 skill 的 description 恰好包含"零钱兑换""贪心更快"等更贴近字面的触发词）。
  - **建议**：把"贪心算法是不是更快/为什么还要用DP"这一类语言信号补充进 description 或 A2 的"语言信号"清单，作为第 6 条触发短语（如"用贪心不是更快吗""为什么不用贪心""greedy vs dynamic programming"），让顶层粗筛就能直接命中，不必依赖 agent 读完全文才能补救。这是一个**精确度加固建议**，不构成本轮测试的 FAIL，因为现有内容仍能在读完全文后给出正确结论。
