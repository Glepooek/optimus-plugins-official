# search-algorithm-selection

> 版本：1.1.1 | 分类：decision

用户在存储结构已确定的前提下，纠结"该用什么算法查找数据"时，给出基于《Hello 算法》的二分查找三前提与哈希/树查找取舍框架。

## 触发词 / 内部触发条件

该用二分查找还是线性查找、要不要为了查找快维护有序索引、哈希查找和树查找该选哪个、binary search or linear search、hash lookup vs tree lookup

## 业务逻辑流程图

```
┌─────────────────────────────┐
│ Step 1: 确认存储结构与数据特征 │
│ 结构/规模/更新频率            │
└────────────┬──────────────────┘
             ▼
┌─────────────────────────────┐
│ Step 2: 核对二分查找三个前提   │
│ 数组存储/已有序/数据量足够大   │
└────────────┬──────────────────┘
             ▼
┌─────────────────────────────┐
│ Step 3: 哈希查找 vs 树查找取舍 │
│ 精确查找用哈希，有序/范围用树   │
└────────────┬──────────────────┘
             ▼
┌─────────────────────────────┐
│ Step 4: 输出结构化建议        │
│ 结论+前提核对+条件性说明       │
└──────────────────────────────┘
```

## 产出物数据流

用户的查找场景描述（存储结构/数据规模/更新频率） → search-algorithm-selection → 结构化选型建议
（查找算法结论 + 前提核对 + 条件性说明） → 人工接手，写入实际代码
