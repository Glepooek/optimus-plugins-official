# summaries.md 模板

**回答**：为什么这么选。**恢复时按需读**——仅当要改动上轮的决定时。

**写作取向：可以详细**。只在需要时才付读取成本，所以这一层不必压缩——决策的完整论证过程应该写在这里，而不是挤进 `progress.md`。

---

## 格式

```markdown
---
task: <任务主题>
date: <YYYY-MM-DD>
---

# <任务主题> · 决策与权衡

## 会话 N — <YYYY-MM-DD>

### 关键决策

- **<决策>**：<为什么这么选>

### 方案权衡

- **放弃的方案**：<方案>
  **放弃原因**：<原因>

### 遗留风险

- <已知但未处理的风险点>

### 待验证的假设

- <当前基于什么假设在推进，这个假设怎么验证>
```

## 四个维度各自防的是什么

| 维度 | 防止下轮 |
|---|---|
| 关键决策 | 无意中推翻已论证过的选择 |
| 方案权衡 | 把已经论证不可行的方案重新提一遍 |
| 遗留风险 | 在已知会塌的地方继续加码 |
| 待验证的假设 | 把未验证的前提当成事实 |

**「方案权衡」最容易被略过，但它是纯增量价值**——git 与 CHANGELOG 都只记录做了什么，不记录**没做什么以及为什么**。放弃的方案不写下来，下个会话会重新提出、重新论证、重新放弃。

**「遗留风险」与「待验证的假设」性质不同**：风险是已知的坏事，要防；假设是尚不知好坏的前提，要验。混为一谈会让真正需要验证的东西被当成"已知风险"搁置。

⚠️ **「遗留风险」里可执行的项要同步进 `progress.md` 的待办队列**（对应那份检查清单的第 5 项）。只写在这里等于埋了个下轮读不到的雷——这一层是按需读的。

## 不写什么

⚠️ **框架特性、API 行为、语言语义不写这里**。那是长期有效的知识，该沉淀到项目的知识库或规范文档。写进交接物会让它随任务结束一起变成历史——**归属错了的信息等于丢了**。

判据：这条信息在**这个任务结束后**还有用吗？有 → 它属于知识库，不属于交接物。

## 本层的追加与覆写语义

同一任务的第二次交接：`## 会话 N` 块**整块追加**在文件末尾，旧会话块原样保留；frontmatter 的 `date` **覆写为本轮日期**（它记的是最后更新时间，不是创建时间）。

本层无「当前状态」性质的段落，因此**不存在需要覆写的正文段**——这与 `progress.md` 不同。**本轮本层无内容时，整个文件保持原样不动，连 `date` 也不改**。

会话号 N 与 `progress.md` 保持一致：即使某轮没产出本文件，编号也不重排。**该文件的第一个会话块编号可能不是 1**——上轮无决策、这轮才首次创建本文件时，编号直接从 `progress.md` 的当前轮次起（如「会话 3」）。跳号本身就说明了前两轮本层无产出。

## 本层是否创建

**四个维度全空则整个文件不创建。** 一次纯执行性的会话（照既定计划做完、无决策无踩坑）只产 `progress.md` 是正常的。

单个维度空则**整段删除，不写「（无）」**——占位符比缺失更糟，下一个会话要花时间确认这个「无」是真没有还是忘了写。

❌ `### 遗留风险` + `- （无）`
✅ 整段不出现

⚠️ 判据是**有没有内容**，不是「三层结构要求三个文件」。文件数量不是完整性的证据。
