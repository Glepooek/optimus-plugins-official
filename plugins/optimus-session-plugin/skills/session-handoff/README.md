# session-handoff

> 版本：1.0.0 | 分类：workflow

跨会话交接：会话结束前把「任务当前进行到哪一步」分三层落成文件，新会话读完就能接着干，不必重建上下文。

## 所处层级

```
┌──────────────────────────────────────────────────┐
│  workflow                                        │
│    ★ session-handoff ★                           │
│    weekly-report（同层，输出面向人而非下一会话）    │
├──────────────────────────────────────────────────┤
│  quality / generator / tool / platform / decision │
│    无直接上下游——本 skill 不消费也不产出            │
│    其他 skill 的中间物                             │
└──────────────────────────────────────────────────┘
```

**无上下游 skill 依赖，独立使用。** 交接物的消费者是下一个会话（人或 agent），不是另一个 skill。

## 触发词

**保存**：交接、保存进度、handoff、要下班了、存一下当前状态

**恢复**：继续上次的工作、接着干、上次做到哪了、恢复进度

⚠️ 模式按用户意图判定，不按 `docs/sessions/` 目录是否存在——目录已存在但这次要保存新一轮时，存在性判定会误判为恢复。

## 业务逻辑流程图

```
┌────────────────────────────────────────────┐
│ Step 1  HARD GATE 四项前置校验              │
│         git 仓库 / 分支名 / 模板 / 工作区    │
├────────────────────────────────────────────┤
│ Step 2  路径推导（每次实测，不缓存）         │
│         分支≠默认 → 加 <branch>/ 段         │
│         协作者>1  → 加 .<user> 后缀         │
├────────────────────────────────────────────┤
│ Step 3  模式判定（按用户意图）               │
│         ├─ 保存 → Step 4                   │
│         └─ 恢复 → Step 6                   │
├────────────────────────────────────────────┤
│ Step 4  采集 git 状态 + 按 7 项清单核对待办  │
├────────────────────────────────────────────┤
│ Step 5  三层各自判断是否创建 → 报告路径      │
│         不自动提交                          │
├────────────────────────────────────────────┤
│ Step 6  定位任务目录（多个 → 让用户选）      │
├────────────────────────────────────────────┤
│ Step 7  分层读取：progress + insights 必读   │
│         summaries 仅改动上轮决定时才读       │
├────────────────────────────────────────────┤
│ Step 8  复述三件事 → 停下等指令，不自动开工  │
└────────────────────────────────────────────┘
```

## 产出物数据流

```
会话中的判断与决策
        │
        ▼
  ★ session-handoff ★
        │
        ├→ docs/sessions/<任务>/progress.md    做了什么 + 待办队列（总是产出）
        ├→ docs/sessions/<任务>/insights.md    已核验的事实 / 踩坑 / 习得（有内容才产出）
        └→ docs/sessions/<任务>/summaries.md   决策 / 权衡 / 风险 / 假设（有内容才产出）
                    │
                    ▼
            下一个会话（人工触发恢复）
                    │
                    └→ 踩坑的「归属判定」标为通用规范的
                       由人搬进知识库 / known-issues（不自动搬）
```

⚠️ **后两层允许不产出**——纯执行性会话只产 `progress.md` 是正常的。文件数量不是完整性的证据。

## 依赖关系图

```
        用户显式触发（唯一入口）
                 │
                 ▼
      ★ session-handoff ★
                 │
       ┌─────────┴─────────┐
       │ 只读              │ 只写
       ▼                   ▼
  git log / status    docs/sessions/**
  （采集事实）         （交接物，不提交）
                            │
                            ▼
                    用户自行决定是否提交
                    （本 skill 不调用任何提交流程）
```

**无 skill 调度本 skill，本 skill 也不调度任何 skill。** 交接物写完即止——是否入库、用什么 commit message，由用户按所在仓库的规范自行处理。
