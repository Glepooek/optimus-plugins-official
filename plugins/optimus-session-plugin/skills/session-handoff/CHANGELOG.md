# Changelog

## [1.0.1] - 2026-09-10

darwin-skill 首评（68.4 分）暴露的问题：保存模式从未要求查看已有目录，同一任务第二次交接会凭记忆推 slug，推出近义词就裂成两个目录——两边各有半份待办队列且**不报错**。这条路径恰好是自举验证覆盖不到的（首次交接必然新建目录）。

### Fixed

盲评的逐行执行模拟暴露出五个**会静默出错**的路径——写入成功、零报错，但恢复时找不到：

- **CWD 从未锚定仓库根**。`--is-inside-work-tree` 在任意子目录都返回 true，在 `plugins/foo/` 下交接会建出平行的 `docs/sessions/`。路径推导第一行补 `cd "$(git rev-parse --show-toplevel)"`
- **shell 变量被当成跨调用持久**。`$DEFAULT` 在一个代码块里赋值、在另一次工具调用里引用，展开成空串后 `git log "origin/${DEFAULT}..HEAD"` 变为 `origin/..HEAD` 报错。改为 echo 出实际值再抄进后续命令，并写明原因
- **分支名与用户名未净化**。`feat/coupon` 拼进路径会多出一层目录，比恢复用的 glob 深一层——写得进读不出；`user.name` 常含空格。补 `tr` 净化，原表格示例写 `feat-coupon` 暗示了净化却没写规则
- **定位用的 glob 会把分支层目录列为候选**。`docs/sessions/*/` 同时命中 `docs/sessions/feat-coupon/`，导致「多于一个则 STOP」在特性分支布局下被永久误触发，用户还可能选中不含 md 的空壳。两处 `ls -dt` 均补日期段 `grep` 过滤
- **恢复模式全程无 `.<user>` 后缀**，多人仓库恢复必然落空。补默认读自己那份的规则

以及三处判断错误：

- 前置校验第 2 项把「空仓库」与「detached HEAD」混为一谈，诊断提示给错方向——两者分开处理，前者可继续，后者才终止
- 恢复模式缺零结果分支，找不到交接物时会直接开工。补「列出查过的路径并停下」
- 追加模式未定义 `summaries.md` / `insights.md` 的处理，只说了 `progress.md`。补：只追加会话块、本轮无内容则文件保持原样不动

独立的 dim8 实测（让一个只读本 skill、不接触仓库的 agent 在虚构场景下走完保存流程）复现了变量失效那条，并暴露出四处**规则空白**——执行者只能猜，且不同的猜法产出不同的文件：

- **「工作区状态」本轮为空时**该删段还是保留旧快照，未定义。补：整段删除
- **`summaries.md` / `insights.md` 的 frontmatter `date` 是否更新**，模板只说追加会话块。补：同样覆写，但本轮该层无内容时整个文件不动
- **后两层首次创建时的会话号**该从 1 起还是与 `progress.md` 对齐，SKILL.md 未重申模板里的规则。补：对齐，首个块编号可能是 3
- **上轮的 ⏸️ 阻塞项在阻塞条件解除后**如何处置，无规则。补：做完则移入「已完成」并注明，没做完则改标 🔴/🟡，不留 ⏸️

同轮补掉的表述歧义：`?? docs/sessions/` 自身不记入工作区状态（自指噪声）、`status` 仅在队列清空时才写 `已完成`、收尾输出用裸文件名、echo 出的五个值各自用在哪里、SKILL.md 与模板对「覆写」的措辞对齐。

实测执行者还独立发现三处：

- **「追加会话块」的插入位置**。`progress.md` 末尾是待办队列、`---` 分隔线在会话块之后，字面 append 到文件末尾会把新会话块放到待办队列后面。模板里画了示意图，但 SKILL.md 的分段表只写「追加」二字——看图才能推出正确位置属于运气。分段表改为明写「插入到 `---` 之前」
- **定位目录时的决定性证据不是目录名**。执行者实际是读了候选目录 `progress.md` 的待办队列、发现本轮做的事正是其中一项才确认匹配的，而规则只让看目录名。补：目录名不足以判断时读待办队列
- **「整段覆写」会把仍然有效的意图连同过期快照一起丢掉**。旧段落里两者混在一起（「12 个文件未提交」是过期事实，「等自举验证通过后一次性提交」是仍成立的意图），机械替换丢了不会有提示。模板补这条区分
- SKILL.md 作为入口未给出跳转指引，追加语义的完整定义在模板里。第 3 步补指针

### Fixed（首评 9 条 finding）

- 保存模式新增「第 1 步 · 定位目录」，先 `ls -dt` 查已有目录再决定新建或追加；疑似匹配但拿不准时停下问用户
- 「工作区状态」移出会话块、与待办队列同列覆写语义——它描述当前工作区，留在会话块会累积成多份互相矛盾的历史快照
- `git symbolic-ref refs/remotes/origin/HEAD` 补 `git remote show origin` fallback。该 ref 只有 `git clone` 会创建，`git init` + `git remote add` 的仓库里不存在，缺 fallback 会让这类仓库永远走单层路径
- 收尾输出模板的「两份」改为占位符——原文紧邻着「不要固定写数量」的告诫，自己却示范了被禁止的写法
- 待办清单第 5 项不再以 `summaries.md` 存在为前提，纯执行会话同样要过
- 核心约束补纯执行性会话的 carve-out，解除与「已完成必填」的对撞

### Changed

- `references/templates.md` 拆为 `progress-template.md` / `summaries-template.md` / `insights-template.md` 三份。原本跨三层的「追加语义」与「取舍规则」两节分解进各层——三层的语义本就不同（只有 `progress` 有「队列整段覆写」这条特例），跨层表把特例摊平成了通用规则
- 两处真需停下的地方加 🔴 STOP 显性标记（保存模式的目录归属存疑、恢复模式的复述后等指令），HARD GATE 前两项同步标注；并说明产物里的 🔴 优先级标记与执行指令的 🔴 STOP 是两回事
- Red Flags 表补 shell 变量、CWD、路径净化三条，并去掉「正文已强调的不在此重复」这句自我声明——它与表内前两行是正文原话相矛盾
- 保存与恢复两个模式的小节改为「第 N 步」编号
- 路径推导表从两个极端补全为四种组合，并说明 `AUTHORS` 数的是全部历史作者
- `compatibility` 补 POSIX shell 依赖声明

## [1.0.0] - 2026-09-10

### Added

- 跨会话交接 skill 首个版本，保存与恢复两种模式
- 三层交接物分职责：`progress.md`（做了什么 + 待办队列）/ `summaries.md`（为什么这么选）/ `insights.md`（习得、踩坑、已核验的事实）
- 交接物路径按「分支 × 协作者数」运行时推导，单分支单人时自动退化为扁平路径
- 待办队列四档优先级（🔴高 / 🟡中 / 🔵低 / ⏸️阻塞），阻塞项与「先不做」项强制附原因
- 待办队列 7 项写入检查清单，把「有没有漏记待办」从凭感觉变成可逐项核对
- 恢复时分层读取：`progress` 与 `insights` 必读，`summaries` 仅在要改动上轮决定时读
- 同任务第二次交接的追加语义：会话块追加、待办队列整段覆写

### 设计说明

- 参照 `fltrp-session-handoff` v2.1.0，采纳其三层分职责结构、按人隔离、待办队列四档与 7 项检查清单
- **不采纳**：静默追写、上下文告急自动保存、交接物自动 commit、`init.sh`、`feature_list.json`、`artifacts.json`、`pitfalls.md` → linter 闭环、stop hook、双 agent 拆分（逐条理由见 spec 对照表）
- 第三层由参照实现的「逐轮对话记录」改为「习得与核验」——逐轮记录依赖静默追写才成立，仅显式触发时回溯补写既不可靠（早期轮次已被 context 压缩）也无价值（二手信息）
- 路径由参照实现的「一分支一目录」改为「一任务一目录」——前者隐含「一分支 = 一任务」假设，在长期停留主干的仓库上会让所有内容挤进一个越来越长的文件
- 后两层允许整个文件不创建（与参照实现相反）——纯执行性会话只产 `progress.md` 是正常的，强制凑齐会让后两层充满空洞内容

### 已知限制

- **多人协作场景未经实测**——开发仓库只有单一提交者，`.<user>` 后缀展开逻辑仅经静态审查
- **非 master 默认分支未经实测**——开发仓库默认分支为 master，`git symbolic-ref` 回退逻辑仅经静态审查
