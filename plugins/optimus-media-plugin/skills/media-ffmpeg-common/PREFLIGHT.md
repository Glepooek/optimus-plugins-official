# 前置校验流程（media-* 写操作 skill 共用）

本文承载 media-* 系列中**产出文件的 skill** 共用的 Step 0-3 前置校验流程，各 skill 不重复抄写这段骨架，只声明自己的必需信息与特有补充项。

## 适用范围

| 适用 | 不适用 | 原因 |
|---|---|---|
| media-resize、media-compress、media-trim、media-framerate、media-convert、media-audio-extract、media-audio-convert、media-frame-extract | media-analyze | 只读查询，无输出路径，无 Step 3 |
| | media-play | 输入含本地文件/网络流两种形态，且需单独检测 `ffplay`（非 `ffmpeg`/`ffprobe`），校验路径与本文不同 |
| | media-download | 输入是 URL 而非本地文件（做格式校验而非存在性校验），且依赖 `yt-dlp` 与 `ffmpeg` 两个独立工具 |

适用的 8 个 skill 都满足同一组前提：输入是本地文件、产出本地文件、只依赖 `ffmpeg`/`ffprobe`。产出物类型（视频/音频/图片）不影响前置校验流程，因此音频与抽帧类 skill 同样适用。

不适用的三个 skill 在各自 SKILL.md 内维护自己的 Step 0-3，不引用本文——它们的差异是本质性的（输入形态、依赖工具、有无输出），强行收敛会引入比重复更多的分支说明。三者共用的仍是 `REFERENCE.md` 的通用报错处理表与 `INSTALL.md`，与本文无引用关系。

## Step 0：需求预告

处理用户请求的第一步：对比本 skill 需要的信息与用户在触发语句或上下文中已提供的信息，一次性列出缺失项统一询问，不逐个 Step 反应式追问。

- **必需信息**由各 skill 在自己的 SKILL.md 中声明（通常为：输入文件路径、输出文件路径，加该 skill 特有的运行条件参数如目标分辨率/目标帧率/起止时间点）。用户已明确提供的项不重复询问；若必需信息已齐全，跳过本步骤直接进入 Step 1
- **有默认取值的参数不属于必需信息**，缺失不阻塞（如截取模式默认快速、CRF 默认 23），各 skill 自行声明
- **ffmpeg 依赖是否安装不参与本环节比对**：这是系统状态而非用户可主动提供的信息，不作为缺失项询问用户，也不影响是否跳过本步骤的判断；依赖状态由 Step 1 实际检测

本步骤不做实际系统调用（不检测 ffmpeg 是否真的安装、不检测文件是否真的存在），仅做信息是否齐全的静态比对，实际检测由 Step 1-3 完成。

🔴 **CHECKPOINT**：必需信息存在缺失时，必须在此处停下一次性询问用户，禁止带着缺失信息继续往下执行。

## Step 1：确认环境

执行 `REFERENCE.md` 中的环境检测命令，确认 `ffmpeg` 可用。

⛔ **STOP**：检查失败（命令不存在）时，引导用户参考 `INSTALL.md` 安装，返回错误信息并终止任务，不进入后续步骤。

## Step 2：校验输入文件

检查用户提供的输入文件路径是否存在。

⛔ **STOP**：路径不存在时，返回错误信息告知用户核对路径，终止任务，不进入后续步骤。

## Step 3：确认输出路径

🔴 **CHECKPOINT**：向用户确认或根据上下文给出明确的输出文件路径，不得省略直接执行；未确认前不得进入 Step 4。

确认路径后依次做以下两项校验：

**① 父目录存在且可写**

⛔ **STOP**：父目录不存在或无写权限时返回错误信息告知用户，终止任务。

输出文件本身此刻不存在属正常状态，**不作为失败条件**——也不检查它是否已存在，覆盖行为由下方「覆盖策略」统一约定，不属于本步骤的校验范畴。

**② 输出路径不得与输入路径相同**

⛔ **STOP**：输出路径与输入路径指向同一文件时（含相对路径/绝对路径写法不同但实际同一文件的情况），返回错误信息要求用户改用其他输出路径，终止任务，不进入 Step 4。

这是**硬约束**，不可通过用户确认绕过：ffmpeg 会在读取源文件的同时向同一路径写入，导致源文件被截断、产出文件损坏，且原始数据不可恢复。命令统一带 `-y`（见下）后 ffmpeg 不再交互询问，这条校验是唯一的拦截点。

## 覆盖策略

所有产出文件的 ffmpeg 命令**统一带 `-y`**，即目标路径已有同名文件时直接覆盖，不交互询问。

原因：Claude 以非交互方式执行命令，stdin 不可用。不带 `-y` 时 ffmpeg 检测到输出文件已存在会打印 `Overwrite? [y/N]` 等待输入，结果是读到 EOF 后打印 `Not overwriting - exiting` 静默失败，或直接阻塞——两种结果都让任务失败且报错原因隐晦，与"文件已存在"这个真实原因看不出关联。

带 `-y` 的前提是 Step 3 的两项校验都已通过，尤其是②——`-y` 消掉了 ffmpeg 对"输入输出同名"的最后一道交互防线，缺了②就会把用户源文件毁掉。**不得只加 `-y` 而不做②的校验。**

用户明确要求"已存在就不要覆盖"时，改用 `-n`（存在则跳过并退出），不改动其余参数。

## 通用失败处理

以下失败场景对适用本文的 8 个 skill 通用，各 skill 的「失败处理」章节只列本 skill 特有场景，不重复抄写下表。执行中才暴露的 ffmpeg 报错另见 `REFERENCE.md` 的通用报错处理表（该表对全部 media-* skill 生效，含不适用本文的 analyze/play/download）。

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| Step 1：`ffmpeg`/`ffprobe` 命令不存在 | 引导用户参考 `INSTALL.md` 安装，安装后需重新打开终端使 PATH 生效 | 已按文档安装仍报命令不存在：提示检查 PATH 环境变量是否真正写入生效，或改用完整可执行文件路径调用 |
| Step 2：输入文件路径不存在 | 提示用户核对路径拼写、盘符、多余引号或转义字符 | 路径含中文/空格导致解析异常：改用不含特殊字符的路径，或确认终端编码设置正确 |
| Step 3：输出目录不存在 | 提示用户确认目录路径或改用已存在的目录 | 用户坚持要求写入不存在的目录：明确询问是否需要 Claude 代为创建该目录，不得未经确认擅自 `mkdir` |
| Step 3：输出目录存在但无写权限 | 提示用户更换有写权限的输出目录 | 权限问题实为目标文件被其他程序占用（非目录权限本身）：参考 `REFERENCE.md` 的 `Permission denied` 处理建议 |
| Step 3：输出路径与输入路径相同 | 提示用户改用其他输出路径或输出文件名 | 用户坚持要求原地覆盖：说明 ffmpeg 无法原地改写文件，需先输出到临时路径、确认产出正常后再由用户自行替换原文件 |
| 执行阶段：命令因磁盘空间不足中断 | 提示用户清理输出磁盘空间，或改用其他有足够剩余空间的磁盘作为输出路径 | 清理后仍中断：改用 `-crf` 更高（画质更低、体积更小）的档位重试，或换用更大容量的存储设备 |
| 执行阶段：报编码器错误（如 `Unknown encoder`） | 参见 `REFERENCE.md` 的 `Unknown encoder 'libx264'` 处理建议，确认 ffmpeg 构建是否包含该编码器 | 更换完整编码器构建后仍报同一错误：文件本身的视频流可能已损坏，改用 `ffprobe` 复核该流是否可正常读取 |

## 不要做什么（前置校验部分）

以下反例对适用本文的 skill 通用，各 skill 的「不要做什么」章节只列本 skill 特有反例，不重复抄写下列各条。

- 不要在 ffmpeg 环境检测失败时继续执行，应立即返回错误信息并终止（Step 1）
- 不要在输入文件路径不存在时继续执行，应立即返回错误信息并终止（Step 2）
- 不要在用户未确认输出路径前执行命令（Step 3 的检查点）
- 不要在输出目录不存在或不可写时继续执行，应立即返回错误信息并终止（Step 3）
- 不要在输出路径与输入路径相同时继续执行，应立即返回错误信息并终止（Step 3 ②，硬约束不可用户确认绕过）
- 不要省略命令中的 `-y`——Claude 非交互执行下，缺 `-y` 会在输出文件已存在时静默失败或阻塞
- 不要在检查输出路径时把"输出文件尚不存在"判定为失败——未生成前不存在是正常状态
