# Changelog

## [1.1.3] - 2026-08-26

### Changed
- Step 5 两种截取模式补充概念引用：流复制 vs 转码指向 `knowledge-base/media/reference/media-stream-basics.md` §3；"对齐到最近关键帧"中的关键帧概念指向 `video-codecs.md` 的关键帧小节

## [1.1.2] - 2026-08-14

### Fixed
- Step 4 执行前校验区分"ffprobe 查询本身失败（文件损坏/编码不支持）"与"查询成功但时间超总时长"两种失败分支，此前只处理后者，前者会误落入通用报错表造成循环引用式建议；"不要做什么"章节同步新增对应反例

## [1.1.1] - 2026-08-13

### Changed
- 失败处理章节的跨 skill 边界声明补充 `-r` 帧率参数，用户同时提出帧率转换诉求时应另行调用新增的 `media-framerate` skill

## [1.1.0] - 2026-08-13

### Added
- 新增 Step 0"需求预告"：处理请求第一步对比 skill 所需信息与用户已提供信息，一次性列出缺失项统一询问；输入/起止时间/输出路径缺失则询问，截取模式有默认值不阻塞；ffmpeg 依赖不参与本环节比对，由 Step 1 实际检测
- 新增 Step"校验输入文件"（输入参数检查）：输入路径不存在时报错终止
- "确认输出路径与截取模式"步骤标记 🔴 CHECKPOINT 用于确认输出路径；同时新增输出目录可写校验（输出参数检查，目录不存在或不可写时报错终止）
- 新增独立的"执行前校验" Step（运行条件检查，硬约束）：主动调用 media-analyze 查询视频总时长，判断起止时间是否落在合法区间，超出直接报错终止，不带 CHECKPOINT（该场景无法通过用户确认继续，与可协商风险类的 CHECKPOINT 语义不同）
- Step 1 环境检测明确失败时的报错终止行为
- 新增"不要做什么"章节，列出 5 条反例

### Changed
- "起始时间超过视频总时长"从"失败处理"表迁移至独立的"执行前校验" Step——此前是被动等待 ffmpeg 报错/用户发现，现在是执行前主动探测
- Step 编号整体调整：新增 Step0/Step2/Step4，原 Step2（输出路径与模式）→ Step3，原 Step3（执行截取）→ Step5
- README"产出物数据流"与"Skill 依赖关系图"同步更新：media-trim 对 media-analyze 从"失败处理时提示用户参考"改为"执行前校验主动调用"，构成实际调用依赖

## [1.0.1] - 2026-08-13

### Added
- 失败处理章节新增组合请求边界说明，指向 `media-ffmpeg-common/REFERENCE.md` 的"组合请求处理约定"

## [1.0.0] - 2026-08-12

### Added
- 新增 media-trim skill：基于 ffmpeg `-ss`/`-to` 实现音视频片段截取，默认流复制快速模式，提供帧精确的重新编码模式作为备选
