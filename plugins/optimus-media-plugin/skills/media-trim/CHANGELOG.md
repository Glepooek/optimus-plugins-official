# Changelog

## [1.1.4] - 2026-09-01

### Fixed
- 快速模式与精确模式的命令模板均补上 `-y`：Claude 非交互执行下，缺 `-y` 会在输出文件已存在时让 ffmpeg 等待 stdin，结果是静默失败（`Not overwriting - exiting`）或阻塞，且报错原因与"文件已存在"看不出关联。`../media-ffmpeg-common/REFERENCE.md` 与 `CLI-REFERENCE.md` 早已声明该用 `-y`，命令模板未落实
- Step 5 补充 `-y` 与 seek 语义的关系说明：`-y` 作为全局选项固定放在命令最前，位于 `-i` 之前但不参与"输入端 seek / 输出端 seek"的判断，避免后续维护者误读为 `-ss` 位置规则被打破
- 「失败处理」末段与「不要做什么」修正 `-crf` 表述的自相矛盾：原文写"不要在本 skill 命令中叠加 `-crf`"，而精确模式命令本身带固定的 `-crf 18`，改为区分"固定画质档位"与"作为压缩手段的可调 CRF"

### Changed
- Step 0-3 收敛为引用 `../media-ffmpeg-common/PREFLIGHT.md`，本 skill 只声明必需信息（输入文件路径、起止时间点、输出文件路径）、默认项（截取模式默认快速）与 Step 3 的追加确认项（截取模式选择）；Step 4/5 编号不变，不影响正文内既有的 Step 交叉引用
- 「失败处理」「不要做什么」的通用条目收敛到 PREFLIGHT.md，本文只保留特有场景；「不要做什么」新增一条特有反例（不得互换 `-ss`/`-to` 与 `-i` 的相对顺序），此前该约束只写在 Step 5 正文的 ⚠️ 提示里，未进入反例清单

## [1.1.0] - 2026-08-13

### Added
- 新增 Step 0"需求预告"：处理请求第一步对比 skill 所需信息与用户已提供信息，一次性列出缺失项统一询问；输入/起止时间/输出路径缺失则询问，截取模式有默认值不阻塞；ffmpeg 依赖不参与本环节比对，由 Step 1 实际检测
- 新增 Step"校验输入文件"（输入参数检查）：输入路径不存在时报错终止
- "确认输出路径与截取模式"步骤标记 🔴 CHECKPOINT 用于确认输出路径；同时新增输出目录可写校验（输出参数检查，目录不存在或不可写时报错终止）
- 新增独立的"执行前校验" Step（运行条件检查，硬约束）：主动调用 media-analyze 查询视频总时长，判断起止时间是否落在合法区间，超出直接报错终止，不带 CHECKPOINT（该场景无法通过用户确认继续，与可协商风险类的 CHECKPOINT 语义不同）
- Step 1 环境检测明确失败时的报错终止行为
- 新增"不要做什么"章节，列出 5 条反例

### Changed
- "起始时间超过视频总时长"从"失败处理"表迁移至独立的"执行前校验" Step——此前是被动等待 ffmpeg 报错/用户发现，现在是执行前主动探测
- Step 编号整体调整：新增 Step0/Step2/Step4，原 Step2（输出路径与模式）→ Step3，原 Step3（执行截取）→ Step5
- README"产出物数据流"与"Skill 依赖关系图"同步更新：media-trim 对 media-analyze 从"失败处理时提示用户参考"改为"执行前校验主动调用"，构成实际调用依赖
