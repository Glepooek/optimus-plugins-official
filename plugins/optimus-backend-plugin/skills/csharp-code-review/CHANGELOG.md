# Changelog

## [1.5.4] - 2026-08-28

### Fixed
- 审查清单 #8/#9/#10 的 `§ 章节号` 引用补上标题文本（如 `§ 1` → `§ 1. 失败表达`）。裸章节号在规范文件重编号后会静默指向别的内容且无法被自动校验，补标题后可由 `knowledge-base-maintain` 的 `check_refs.py` 交叉校验

## [1.5.3] - 2026-08-27

### Fixed
- 审查清单的 knowledge-base 引用路径同步知识库目录调整：`NN-*.md` → `rules/NN-*.md`（知识库 2.0.0 将各领域规范文件迁入 `<domain>/rules/`，旧路径已失效）

## [1.5.2] - 2026-08-23

### Changed
- 审查清单合并原 #2「类型使用」与 #4「逻辑运算符与判空」两行（同引用 `02-coding-style.md` § 2.2，重复引用同一依据）为一行「类型、运算符与判空」，11 类精简为 10 类，后续编号及快速初审引用同步顺移

## [1.5.1] - 2026-08-22

### Changed
- 范围护栏"先定边界再扫描"升级为 🔴 CHECKPOINT：确需全仓扫描时须用户明确同意，默认不擅自扩大到全仓（检查点显性视觉标记）

## [1.5.0] - 2026-08-22

### Added
- 输入模式扩展：从纯粘贴审查升级为「粘贴 + 扫描本地代码库」，支持用 Glob/Grep 定位待审项目文件（frontmatter 的 compatibility 与 allowed-tools 同步更新为 Read Grep Glob）
- 审查流程新增「确定审查范围」步骤：按「明确指定 → 模块定位 → git diff 改动 → 单点兜底」四层优先级从窄到宽收敛，除非用户明确要求否则不越过当前层级
- 新增「范围护栏」章节：先定边界再扫描、单次审查文件数可控、范围写进报告，避免无边界全仓扫描导致报告失控
- 审查流程第 4 步生成报告时要求"审查摘要"注明实际覆盖范围（文件/目录）

## [1.4.2] - 2026-08-22

### Changed
- 概述改为指向团队 `knowledge-base/csharp/` 规范集，与"Microsoft 官方文档降级为背景"的定位对齐
- 审查流程重构：加入档位决策分支（时间紧走快速初审 / 全面走完整 11 类），原「快速审查清单」改名「快速初审」并标注覆盖子集与升级路径

### Fixed
- 权威参考中 `knowledge-base/csharp/README.md` 坏链修复为 `00-README.md`

## [1.4.1] - 2026-08-22

### Changed
- 审查清单 12 类别合并为 11 行引用表，改为引用 `knowledge-base/csharp/` 规范条款，不再自建重复规则文本
- 删除与审查清单重复的"常见违规速查表"整节
- 权威参考改为以 `knowledge-base/csharp/` 为团队规范准绳，Microsoft 官方文档降级为背景参考

## [1.4.0] - 2026-07-08

### Added
- fallback 表新增一行：修正代码用到 C# 9+ 新语法时须注明所需最低版本，无法确认用户项目 langVersion 时提供兼容旧版本的替代写法（此前完全没有覆盖此风险，若用户项目是 .NET 6 及更早，照搬修正代码会编译不通过）

## [1.3.0] - 2026-07-08

### Added
- 新增「⛔ 不要做什么（反例黑名单）」章节，6 条反模式（编造违规凑数、只查风格忽视健壮性、severity 凭直觉判定、臆测不完整代码、省略修正代码、过度严格化）

## [1.2.0] - 2026-07-08

### Added
- 报告格式后新增「触发条件/一线处理/仍失败兜底」fallback 表，覆盖未提供代码、代码不完整、非 C# 代码、零违规、严重级别判定歧义五种边界场景
- 明确严重级别判定原则：会导致 bug/崩溃/安全漏洞 → 🔴，仅影响可维护性/风格 → 🟡（解决实测中"公共字段未封装"判级不一致的问题）

## [1.1.0] - 2026-07-08

### Added
- 新增第 12 类审查类别「API 设计与健壮性」：异常处理语义统一、取消令牌传播、隐式依赖契约说明、异常不能被静默吞没
- 速查表补充异常吞没、缺少取消令牌两条常见违规
- 快速审查清单补充健壮性检查项
