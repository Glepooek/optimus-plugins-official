# 07 · 性能

> 更新历史：2026-08-21 创建。

性能规范的核心不是"处处优化"，而是**只在测量后优化**。本篇约束防止两类错误：过早优化（浪费复杂度）与瓶颈漏查（浪费吞吐）。

## 1. 原则：先测量再优化

- **必须**：优化前用 profiler / 基准证明瓶颈所在；禁止凭直觉优化
- **应该**：热点路径用 BenchmarkDotNet 记录基线，优化前后对比
- **禁止**：为"可能慢"提前优化普通路径（过早优化是复杂度的主要来源）

## 2. 热点路径识别

- **认知**：热点路径 = 循环内部、高频调用、请求处理主干、大数据集处理
- **必须**：热点路径避免分配（allocation-free）、避免 LINQ 大对象与匿名类型装箱
- **应该**：热点路径用 `Span`、预分配、缓存（见 `06` 章）

## 3. LINQ 边界

- **必须**：普通数据管道用 LINQ（可读性优先，绝大多数场景）
- **禁止**：热路径依赖 LINQ 延迟执行造成**多次枚举**——先 `ToList()` / `ToArray()` 快照再复用
- **禁止**：长链 `Where(...).Where(...).Select(...)` 在热点产生大量中间对象——必要处合并
- **禁止**：LINQ 每元素执行高成本调用（如循环内做 I/O）
- **应该**：大数据集投影避免匿名类型逐元素分配

## 4. 字符串

- **必须**：循环 / 多次拼接用 `StringBuilder`
- **应该**：固定数量拼接用字符串插值（编译器优化为 `StringBuilder`）
- **必须**：字符串比较显式指定 `StringComparison`（`Ordinal` / `OrdinalIgnoreCase`），避免文化差异带来的开销与错误
- **禁止**：热路径逐次 `new Regex(pattern)`——复用静态编译正则或使用 Regex Source Generator

## 5. 集合预分配

- **必须**：已知规模时用构造函数 `capacity` 预分配（`List` / `Array` / `Dictionary`）
- **应该**：高频增长的集合给合理初始容量，避免反复扩容拷贝
- **禁止**：可预估规模的集合不设容量，导致 O(n) 扩容

## 6. 避免装箱

- **认知**：值类型转为 `object` / 接口 = 装箱，产生分配
- **必须**：泛型集合优先（`List<int>`，而非 `ArrayList`）
- **禁止**：热路径值类型隐式装箱（大量 `string.Format` 参数、`object` 参数 API）
- **应该**：哈希场景用 `HashSet<T>` / `Dictionary<TKey,TValue>`，不装箱

## 7. 缓存

- **必须**：缓存设大小上限与过期策略；禁止无界缓存
- **应该**：用 `IMemoryCache`（内置过期 / 上限 / 依赖）而非手写字典
- **禁止**：缓存可变对象不经防御拷贝直接暴露——调用方修改会破坏缓存一致性
- **禁止**：缓存键对象泄漏（键不可变且可安全哈希）

## 8. 反射

- **禁止**：热路径使用反射（`Activator.CreateInstance`、`GetMethod` 等）
- **应该**：用编译期替代：泛型、接口、source generator、预编译表达式树
- **必须**：确实需要反射时缓存 `MethodInfo` / `Delegate`，不逐次查找

## 9. 异步性能

- **必须**：I/O 绑定用异步，不阻塞线程池（见 `04` 章）
- **禁止**：异步路径 `.Result` / `.Wait()` 阻塞（线程池饥饿）
- **应该**：热路径且结果常同步完成用 `ValueTask`（见 `04` 章）
- **禁止**：`async` 方法内执行同步长任务占用线程池线程

## 10. 并发与数据

- **应该**：多线程读写用并发集合（`ConcurrentDictionary` 等）而非手动锁（见 `08` 章）
- **必须**：锁内只做最小工作，不执行 I/O / 慢操作

## 11. 基准测试

- **必须**：性能结论基于基准数据（BenchmarkDotNet），禁止口头"感觉慢"
- **应该**：基准与业务代码分离（独立基准项目），不混入单元测试
