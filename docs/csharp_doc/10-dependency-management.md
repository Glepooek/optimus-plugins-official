# 10 · 依赖管理与 NuGet（CPM）

> 更新历史：2026-08-21 创建。

依赖是供应链安全的入口（见 `14` 章第 6 节）。本篇强制中央包管理（CPM）、版本锁定与引入审批。存量仓库迁移用 `dotnet-nuget:convert-to-cpm` skill。

## 1. 中央包管理（CPM）——必须

- **必须**：使用 CPM，通过 `Directory.Packages.props` 集中管理包版本
- **必须**：所有 `PackageReference` 不写 `Version`，版本只存在于 `Directory.Packages.props`
- **禁止**：项目内单独写包版本（版本漂移的根源）
- **应该**：通用依赖提升为全局（无条件）条目，项目特有依赖放入对应的条件 ItemGroup

## 2. 版本策略

- **必须**：锁定精确版本，禁止浮动版本（`*`、`1.x`）
- **必须**：生产依赖禁止预发布包（`-preview` / `-rc` / `-beta`），评审通过除外
- **应该**：定期检查过期依赖（`dotnet list package --outdated`），升级走 PR + review
- **必须**：升级依赖后运行全量构建与测试，验证兼容性
- **应该**：依赖升级记录到 CHANGELOG（联动 `16` 章）

## 3. 包来源

- **必须**：用仓库级 `NuGet.config` 固化包源（`nuget.org` + 私有源）
- **禁止**：个人机器临时添加来源，导致构建不可复现
- **必须**：CI 与本地使用同一份 `NuGet.config`
- **应该**：私有源凭据走环境变量 / 密钥管理，不提交到仓库

## 4. 漏洞与安全

- **必须**：CI 执行依赖漏洞扫描（`dotnet list package --vulnerable` 或审计工具）
- **必须**：已知可利用漏洞的依赖立即升级；无法升级须评审豁免并登记
- **应该**：启用依赖机器人（Dependabot 等）自动检测并提交升级 PR

## 5. 许可证合规

- **必须**：引入第三方包前确认许可证与团队合规要求兼容
- **禁止**：引入 GPL / AGPL 系（传染性）依赖，除非法务明确批准
- **应该**：定期导出依赖清单（license report）用于审计

## 6. 引入审批

- **必须**：新增包需说明：解决什么问题、替代方案、体积与许可证、维护活跃度
- **禁止**：为"一行功能"引入重量级包（先评估标准库与已有依赖能否覆盖）
- **应该**：优先官方 / 主流维护的包；关注 stars、更新频率、issue 响应速度

## 7. 禁止的包类型

- **禁止**：不必要的反射 / 动态生成框架（性能与可维护性，见 `07` 章）
- **禁止**：功能重叠的多包并存（如多个日志库——见 `11` 章统一选型）
- **禁止**：直接引用非 SDK 管理的二进制，除非经过安全评审
