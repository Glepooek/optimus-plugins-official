# 11 · 日志与可观测性

> 更新历史：2026-08-21 创建。

可观测性三支柱：日志（Logs）、指标（Metrics）、追踪（Traces）。本篇强制统一日志选型、级别语义与结构化，并串联关联 ID。异常日志规范联动 `05` 章第 8 节；敏感数据保护联动 `14` 章。

## 1. 日志库统一

- **必须**：全仓库统一日志方案（Serilog 或 `Microsoft.Extensions.Logging` + 统一提供者），禁止混用多个日志库
- **应该**：业务代码通过 `ILogger<T>` 抽象记录日志，不直接依赖具体库 API（便于替换与测试）
- **禁止**：业务代码手写 `Console.WriteLine` 输出日志

## 2. 日志级别语义

| 级别 | 语义 |
|---|---|
| `Trace` | 诊断级，生产默认关闭 |
| `Debug` | 开发调试，生产按需开启 |
| `Information` | 正常运行状态：启动、请求完成、业务里程碑 |
| `Warning` | 可恢复异常 / 降级（重试成功、兜底命中） |
| `Error` | 影响功能的错误（请求失败、外部依赖故障） |
| `Critical` | 进程 / 系统级致命 |

- **必须**：错误日志携带异常对象（`Log.Error(ex, "...")`），保留堆栈与内部异常（联动 `05` 章第 8 节）
- **禁止**：把正常业务路径打成 `Error` / `Warning`（日志噪音的根源）

## 3. 结构化日志

- **必须**：使用结构化日志——消息模板 + 命名参数，禁止字符串拼接拼消息
- **应该**：`Log.Information("Order {OrderId} created", orderId)`，而非 `$"Order {orderId} created"`
- **禁止**：日志中出现敏感数据（密码、Token、完整 PII）——见 `14` 章
- **应该**：模板参数名保持稳定（日志查询与告警依赖字段名）

## 4. 上下文关联

- **必须**：跨请求 / 跨服务传递关联 ID（correlation id），日志携带请求 ID / 用户 ID / 业务 ID
- **应该**：用日志作用域（`BeginScope`）自动附加上下文，而非每个日志手动传参
- **禁止**：缺失关联信息导致故障无法串联（排查路径断裂）
- **应该**：日志 / 指标 / 追踪共享同一关联 ID（见第 7 节）

## 5. 日志性能

- **必须**：热路径日志控制在合理级别，避免高频 `Information`
- **应该**：结构化日志天然延迟求值——未启用的级别不渲染消息体，利用这一点而非手动拼接
- **禁止**：日志调用内做昂贵计算（即使该级别被过滤）

## 6. 日志噪声控制

- **必须**：避免"每循环一条""每元素一条"的日志风暴
- **应该**：高频日志抽样或按周期汇总
- **禁止**：把临时调试日志提交进代码库（遗留噪音）
- **应该**：上线前检查日志级别配置，确认生产落盘量合理

## 7. 指标与追踪

- **应该**：关键业务指标（吞吐、延迟、错误率）通过统一管道（如 OpenTelemetry）暴露
- **应该**：分布式调用链用 OpenTelemetry 追踪，与服务边界传递 trace / span context
- **必须**：指标 / 追踪的埋点生命周期受管理，临时排障埋点及时清理
- **禁止**：业务代码堆自定义指标框架，绕过统一管道

## 8. 配置

- **必须**：日志级别通过配置（`appsettings`）控制，不硬编码
- **必须**：日志输出目标（控制台 / 文件 / 收集器）由配置决定，代码不写死
- **禁止**：连接串、密钥等敏感配置写入日志（见 `14` 章）
- **应该**：多环境（开发 / 测试 / 生产）维护各自的日志级别与输出配置
