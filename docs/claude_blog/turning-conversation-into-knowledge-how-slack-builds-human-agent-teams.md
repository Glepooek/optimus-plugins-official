# 把对话转化为知识：Slack 如何构建人机协作团队

Jaime Delanghe 于 2017 年加入 Slack，负责搜索与机器学习，其使命是把职场对话转化为组织的机构性知识。如今作为公司的首席产品官，她从一开始就相信：要实现这个目标，人必须公开地工作——把对话、决策和进行中的工作都留在公司里任何人都能阅读和检索的频道里。在她近期的文章[*《工作即对话》*](https://jaimedelanghe.medium.com/the-work-is-the-conversation-50a1d61f8f9e)中，她为智能体提出了同样的主张：围绕工作展开的对话，正是智能体发挥作用所需的上下文，也最终能帮我们实现那个已有数十年历史的目标——把散落的知识转化为生产力。

为了了解这在 Slack 内部具体是什么样子，我们和 Jaime 聊了聊她在构建高效人机协作团队、以及推广这些新工作方式方面的最佳实践。

## 把对话历史当作知识库

多年来，人们一直期待职场对话——人们协作时产生的那些「尾气」——能够复利式地沉淀为组织知识，但这个承诺从未实现。

「我手上有 Slack 早期的大量研究论文，它们表明的结论恰恰相反：对话并不会变成知识，」Jaime 说。「你希望它会，但实际上那只是一大堆挂在那里的东西，人们仍然不得不重复自己说过的话。」

要理清所有这些「尾气」，靠人力根本做不到。而现在，这是智能体的工作。

### 如何落地

- **默认使用公开频道**：智能体只能从它看得见的内容中学习。在私信或私密线程里做出的决策对它们是不可见的——而且会永久地对组织流失。
- **向智能体索取推理过程，而非仅仅是记录**：不要只搜索「决定了什么」，而要让智能体重建*为什么*这么决定，以及此后上下文发生了哪些变化。
- **拓宽覆盖面**：Slack 和 Claude 这类工具正在把会议、邮件、日历和文档仓库缝合到一起——你接入的上下文越多，团队重复自己的次数就越少。

## 学会在智能体与人之间何时交接任务

人机协作团队的核心节奏，是一个不断交接的循环。在 Slack 中由 Claude 驱动，智能体承担生产性工作——起草、总结、监控、准备——然后把结果交给人。人来审阅、决策、调整方向，再把工作交回给智能体去执行下一步。

想看这一切的实际运作，只要看看 Jaime 是怎么开启她这一周的就够了。

「现在是周一早上，我刚看完一个智能体为我生成的每日简报，」Jaime 说。

同样在等她审阅的，还有上一周产品工作坊的回顾（附带已标记的升级事项）、一份全网 AI 进展报告、当天各场会议的会前简报，以及一份她交给智能体重写的过时个人简介。在每一轮循环的末端，都由人来审阅，并基于智能体的行动做出决策。

### 如何落地

- **用智能体生成的简报开启一天。** 回顾、升级事项、会前准备和全网综述，都非常适合交给智能体主导，再由人审阅。
- **把工作锚定在一个共享频道里。** 所有工作都在共享频道中共享，让人和智能体可以一起分诊，由人主导优先级排序。
- **让轻量信号可被执行。** 在 Jaime 的频道里，一个 emoji 表态就会把某一项加入列表，随后由智能体接手这个任务。

## 为智能体分配清晰的角色

如果你的心智模型还停留在一对一的聊天机器人，那么与一支专业化的 Claude 智能体队伍协作会让人无所适从。Jaime 的思路是社会性的，而非技术性的：「我倾向于认为，智能体有点像同事。」

正如人类队友有各自的角色与职责，智能体也应该有清晰的目标和专注领域。「如果一个智能体的价值感觉像是被强制指派的，而不是被使用者清晰地感受和理解到的，那就很难记住这东西到底是干什么用的，」她说。

**如何落地：**

- **把常规的事务性任务交给通用智能体。** 与其要求大家记住某个专用工具，不如训练一个智能体来搞定重复性任务，比如提交服务台工单，或者把上周的指标拉进状态更新里。
- **让价值被感受到，而不是被强制推行。** 如果人们说不清某个智能体是干什么用的，也许就该让它退役了。

## 共享频道默认公开；私密要有明确理由

Slack 从最早期就一直推荐默认公开的频道：「你是在构建一种共同理解、一份为后续所有工作服务的共享上下文，」Jaime 说。

她建议除非有具体理由需要给上下文和知识设门槛，否则就让频道保持公开。智能体能够调用并用于指导自身工作的信息越多，它们就能成为越高效的队友。

开放的上下文会产生复利——新人是接入历史而不是面对一个空收件箱，而且没人需要重复自己。现在智能体也从中受益，而这些上下文与工作记忆又会回流给人。

**如何落地：**

- **让常规工作保持公开。** 把非敏感的项目、公告和问答频道设为公开，好让智能体同事获得它们发挥最大作用所需的知识。
- **记住：你的智能体读的就是你的团队读的内容。** 对任何需要汇报该频道情况的智能体来说，一个私密频道就是一个盲区。
- **让心理安全感来决定边界。** 一旦真正敏感的材料被隔离出去，工作退回到私信里的主要原因就不是保密，而是不愿意在过程中被人看见。人们应当有信心在公开场合做日常工作，包括粗糙的草稿和尚未成形的问题，并相信同事会以善意相待。而这种开放本身也会产生复利：「你通过给出信任来获得信任。」

## 通过展示「可能性的艺术」来推广采用

学会一种新工作方式最快的途径，就是看着队友做一遍。Jaime 在 Salesforce 见过这一点：员工们在一个名为 *How I Slackbot* 的全公司频道里分享 skill、调试技巧和工作流窍门，据她统计该频道有数千名成员。在这个默认公开的频道里，一个来自销售流程的窍门，最终可能重塑一条工程流程。

在 Slack 内部，推动产品经理使用 Claude 这件事「是你能想象到的最自组织的过程」。一位 PM 找开发者体验负责人帮他完成了配置，然后写了一份 canvas，展示他做了什么、怎么做的。其他 PM 复制了这个格式。各团队自行组织工作坊，还建起了自己的 git 仓库。

**如何落地：**

- **建立一个全公司的成果分享频道。** 给员工一个公开的地方来分享 skill、调试技巧和工作流窍门，让一个职能的窍门能重塑另一个职能。
- **鼓励别人可以照抄的写作产出。** 一份简短的「我做了什么、怎么做的」文档，就能把一个人的配置变成团队模板或 skill。

## 衡量结果，而非活动量

从在 Slack 的早期开始，Jaime 就一直在跟「如何衡量生产力」这个问题较劲。「我们希望人们发更多消息吗？」她说，「也许并不。发消息可能并不真的意味着他们从 Slack 中获得了更多。消息变多可能意味着人们找不到自己需要的东西，或者第一次没能把话说清楚。」

如今，衡量 AI 价值的问题看起来颇为相似——面对如此复杂的东西，简单的指标起不了作用。token 用量只能告诉你灯是亮着的，虽然这也值得知道，但并不充分。

**如何落地：**

- **把使用量指标当作脉搏检查，而不是价值的证明。** 活动量告诉你采用正在发生，而不是它正在起作用。
- **做好动用你自己判断力的准备。** 没有一种干净的办法能证明人们使用这些工具的方式会带来更好的业务结果。用 Jaime 的话说，要把两者连起来仍然需要「大量的信念跳跃」，没有任何仪表盘或使用统计能替你证明这一点。

## 一起改变你们的工作方式

对于试图落地人机协作团队的组织，Jaime 最重要的建议是重新想象每一条工作流：「我们将不得不弄清楚如何改变我们的工作方式，而不只是把同一类工作做得更多更快。而这将是一项团队运动。」

那么她对构建高效人机协作团队最重要的建议是什么？尽早开始，但从小处开始。把一群人和 Claude 拉进一个共享频道，给他们同一套资源，然后让他们去工作。如果 Slack 的经验有任何参考价值，那么他们构建出来的东西会自行扩散开来。
