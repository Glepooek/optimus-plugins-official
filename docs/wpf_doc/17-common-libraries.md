# 17 · WPF 通用库选型

> 更新历史：2026-08-22 创建。

WPF 的"通用库"主要是**视觉资产**：控件库、主题库、图标库、交互库与 MVVM 框架。这类库选定后全局观感绑定、替换成本极高，选型必须团队统一。本篇只覆盖 **WPF 特有**的库——通用 C# 库（DI、日志、序列化、HttpClient 等）属通用工程约定，不在本篇。

## 1. 选型总原则

- **必须**：WPF 库选型团队统一决策，写入文档并全员知晓，**禁止**个人按偏好各自引入
- **必须**：引入前评估五维——**维护活跃度、许可证、包体积、版本兼容性、主题侵入性**
- **必须**：许可证与使用方式匹配（开源需核对商用条款，如 MIT/Apache 可直接商用，GPL 类受限），**禁止**引入许可证不明的库
- **必须**：依赖统一版本管理（`Directory.Packages.props` 或团队约定），**禁止**各项目各自引版本（联动 `01` 章第 6 节）
- **禁止**：引入维护停止的库（无安全修复与生态跟进，联动 `13` 章第 6 节）

## 2. 五维评估标准

| 维度 | 考察 | 一票否决情形 |
|---|---|---|
| **维护活跃度** | 最近提交时间、Issue 响应、release 频率 | 已归档 / 停止维护 2 年以上 |
| **许可证** | 商用条款、闭源依赖 | GPL 系用于闭源分发、无许可证 |
| **包体积** | 程序集大小、依赖树、对启动的影响 | 引入一个功能拖入整棵重型依赖 |
| **版本兼容性** | 与目标框架 / 其他库的版本匹配 | 与目标框架或已有库冲突无法共存 |
| **主题侵入性** | 是否接管全局样式 / 资源字典 | 强制替换全局默认样式、与现有主题冲突 |

- **必须**：评估结论记录在库选型清单，**禁止**"先引入再说"（移除成本远高于引入）
- **应该**：优先成熟 / 社区广泛采用的库（Bug 多被修、坑多被踩过）
- **禁止**：多套功能重叠的库并存（见第 6 节）

## 3. 控件库

控件库是观感与交互基座，**必须**全仓库统一选型，是替换成本最高的决策。

- **必须**：全仓库统一一个控件库，**禁止**同时引入多个（样式冲突、观感割裂、体积翻倍）
- **必须**：控件库选型前用真实页面原型验证（观感、性能、与现有主题融合），**禁止**仅凭功能清单决策
- **禁止**：为单个控件引入整个控件库（如只要一个 `Card` 就拖入完整套件）

```xml
<!-- ❌ 同时引用多个控件库：样式互相覆盖，全局观感割裂，包体积翻倍 -->
xmlns:mah="http://metro.mahapps.com/winfx/xaml/controls"
xmlns:material="http://materialdesigninxaml.net/winfx/xaml/themes"

<!-- ✅ 全仓库统一一个控件库：样式唯一来源，观感一致 -->
xmlns:material="http://materialdesigninxaml.net/winfx/xaml/themes"
```

| 类别 | 代表性库 | 备注 |
|---|---|---|
| 开源控件库 | MahApps.Metro、MaterialDesignInXamlToolkit、HandyControl、WPF-UI、Fluent.Ribbon（Ribbon） | 按团队观感需求二选一 |
| 商业控件库 | DevExpress、Telerik、ComponentOne | 按许可证与支持选购 |
| 图标库 | MahApps.Metro.IconPacks、FontAwesome.WPF | 随控件库配套选型 |

- **必须**：控件库自带的主题 / 资源字典统一在 `App.xaml` 合并（联动 `02` 章第 2 节、`07` 章），**禁止**各页面单独加载控件库资源
- **必须**：控件库升级前核对主题 / 资源 key 兼容性（升级可能改名或移除），先在测试分支验证再全量升
- **禁止**：混用不同控件库的配套主题资源（`MaterialDesign` 主题配 `MahApps` 样式控件，观感混乱）

## 4. 图标库

- **必须**：图标库团队统一（与控件库配套），**禁止**项目内混用多套图标来源
- **必须**：图标资源在 XAML 中引用统一命名（`{StaticResource XxxIcon}`，联动 `07` 章第 6 节），**禁止**在代码里散落图标路径
- **应该**：常用图标抽为全局资源字典，避免每个控件重复声明
- **禁止**：位图图标当矢量用（分辨率依赖、DPI 放大模糊，联动 `08` 章第 6 节）；优先矢量图标库或 `svg-to-xaml-path` 产物

```xml
<!-- ❌ 位图图标放大模糊：高 DPI / 放大后边缘锯齿 -->
<Button>
  <Image Source="pack://siteoforigin:,,,/icons/save_24.png" Width="24" Height="24" />
</Button>

<!-- ✅ 矢量图标：任意尺寸清晰，颜色可随主题 -->
<Button>
  <ContentControl Content="{StaticResource SaveIconPath}" />
</Button>
```

## 5. 交互库与 MVVM 框架

- **必须**：Behaviors / Interactivity 统一用 `Microsoft.Xaml.Behaviors.Wpf`（选型理由与用法见 `16` 章）
- **必须**：MVVM 框架全仓库统一（选型矩阵见 `03` 章第 1 节，`Prism` / `CommunityToolkit.Mvvm` / 原生三选一），**禁止**混用多套 MVVM 框架
- **禁止**：同时引入 MVVM 框架 + 自行封装半套框架（职责重叠、团队分叉）

```csharp
// ❌ 同一个仓库既用 CommunityToolkit.Mvvm 又自己写一套 ViewModelBase
//    新人困惑"该继承哪个"，两条演进路径分叉
// ✅ 全仓库统一一套 MVVM 框架，所有 ViewModel 继承同一基类
```

- **应该**：对话框 / 消息框增强（如需）随控件库自带能力（MaterialDesign `DialogHost`、MahApps `MetroWindow` 消息），**禁止**单独引一套对话框库与控件库重复
- **禁止**：为动画引入重量级动画库（WPF 原生 `Animation` / `VisualState` 足够，联动 `08` 章）；确需高级动画先评估后再引

## 6. 混用与叠加规则

- **必须**：功能重叠的库**只选一个**（两个日志库、两个对话框库、两个动画库都是反模式）
- **必须**：新增库前先查选型清单是否已有替代，**禁止**为"顺手"引入重叠库
- **应该**：确需引入新库时走评估流程（五维 + 原型验证），结论回写选型清单
- **禁止**：通过引用多个功能互补的库绕开"统一选型"（多个库的样式 / 资源叠加产生不可预期交互）

```csharp
// ❌ 同仓库出现两个日志 / 两个对话框来源：输出路径分裂、样式冲突
// 业务代码里同时 new NLog 和 Serilog，对话框既有 DialogHost 又自定义 MessageBox
// ✅ 每类能力只保留一个实现，其余代码统一迁移到唯一选型
```

## 7. 版本与升级治理

- **必须**：所有 WPF 库版本集中在统一清单管理，**禁止**项目内散落 `PackageReference Version`
- **必须**：升级控件库 / 主题库前核对与目标框架兼容（联动 `01` 章第 6 节），升级后跑全量 UI 走查
- **应该**：锁定小版本（可重复构建），大版本升级走专门任务 + 回归
- **禁止**：控件库 / MVVM 框架大版本升级与业务改动混在同一个提交（隔离风险，便于回滚）
