# 15 · 打包与部署

> 更新历史：2026-08-21 创建。

WPF 应用的交付形态决定安装体验、更新与安全边界。本篇约束打包方式选型、发布配置、更新机制与签名。

## 1. 打包方式选型

| 方式 | 特征 | 适用 |
|---|---|---|
| **MSIX** | 现代安装、自动更新、沙箱可管理 | 企业分发、商店发布、需自动更新 |
| **ClickOnce** | 部署简单、自动更新、按 URL 启动 | 内网 / 快速分发、无商店要求 |
| **自包含发布** | 无运行时依赖、文件夹 / 压缩包 | 用户机无 .NET、便携分发 |
| **框架依赖发布** | 依赖目标机 .NET 运行时 | 内网已装运行时、体积小 |

- **必须**：按目标环境选型——需自动更新 / 商店 / 沙箱用 MSIX；快速内网分发用 ClickOnce；无运行时保证用自包含
- **必须**：团队统一默认打包方式（如 MSIX + 自包含回退），**禁止**每项目各自拍脑袋
- **禁止**：发布产物依赖开发机私有组件（构建机产物直接分发，联动 `01` 章 CI 可复现）

## 2. 发布配置

- **必须**：发布用 Release 配置（`dotnet publish -c Release`），**禁止** Debug 发布（性能 / 调试符号泄露）
- **必须**：发布产物版本号一致（程序集版本 / 文件版本 / 产品版本），**禁止**版本号不匹配（更新判断失效）
- **应该**：冷启动优化发布属性（`PublishReadyToRun`、必要时 `PublishSingleFile`），联动 `10` 章第 6 节
- **应该**：自包含发布带裁剪权衡——裁剪减体积但可能破坏反射 / 动态加载（XAML 反射场景慎用），**禁止**不验证就裁剪
- **禁止**：发布含调试符号（`.pdb`）到生产机（信息泄露风险），CI 归档分离

## 3. 安装与卸载

- **必须**：安装包提供正确的图标 / 名称 / 发布者信息（用户信任与识别）
- **必须**：卸载清理干净（注册表 / 本地数据 / 用户配置），**禁止**残留垃圾
- **应该**：安装前置检查（运行时版本、磁盘空间、依赖），失败给出可操作提示
- **禁止**：安装时静默覆盖用户数据（升级保留配置）

## 4. 更新机制

- **必须**：自动更新校验完整性（下载后校验哈希 / 签名），**禁止**未校验直接覆盖（联动 `13` 章第 5 节）
- **必须**：更新提示用户（大小 / 影响），**禁止**后台静默强制更新到不可回退版本
- **应该**：更新失败回退（保留旧版本 / 事务式替换），**禁止**半更新状态
- **必须**：版本比较正确（语义化版本，`==` 字符串比较不可靠），更新通道（正式 / 预览）明确
- **禁止**：更新包来源不可信（HTTP 明文 / 未签名源）

## 5. 签名与安全发布

- **必须**：发布包代码签名（Authenticode），**禁止**未签名分发（联动 `13` 章第 5 节）
- **必须**：MSIX / ClickOnce 清单签名，更新包同源签名校验
- **应该**：证书有效期管理（续期提醒，过期签名破坏信任）
- **禁止**：把签名证书私钥放构建机明文共享（密钥管理走安全存储）

## 6. 版本管理

- **必须**：版本号按语义化（semver）——破坏性变更升 major，新功能升 minor，修复升 patch
- **必须**：发布版本与 CHANGELOG 同步（用户可见变更记录）
- **应该**：CI 打 tag + 生成发布产物，发布流程脚本化 / 文档化（联动团队协作约定）
- **禁止**：发布流程依赖个人记忆（不文档化）

## 7. 环境与配置

- **必须**：运行配置（连接串、API 地址）按环境区分（开发 / 测试 / 生产），**禁止**生产配置硬编码 / 提交仓库
- **必须**：生产配置经安全通道下发（安装配置 / 用户级配置），**禁止**明文敏感配置入库（联动 `13` 章第 1 节）
- **应该**：配置支持用户级覆盖（`%AppData%`）与应用级默认分离

## 8. 部署验证

- **必须**：发布产物在干净环境验证（无 SDK 的机器 / 虚拟机），**禁止**只在开发机自测
- **必须**：升级路径测试（旧版 → 新版，数据兼容），**禁止**升级破坏旧数据
- **应该**：回滚方案预案（出问题恢复上一版），**禁止**无法回滚的发布
- **禁止**：发布后才发现部署问题（验收清单含安装 / 卸载 / 升级 / 回滚四项）
