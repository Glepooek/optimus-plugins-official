### P4 核实结论：spec 的怀疑被推翻（2026-09-15）

spec §5.3 怀疑 master `skills/avalonia/SKILL.md` Overview 的「**Avalonia 12 is the current stable version; compiled bindings are enabled by default**」是错误事实声明。回一手源核实结果：**两句都正确，Overview 不需要任何修正**，P4 的既定动作（「修正 master Overview」）坍缩为空操作。

| 子claim | 结论 | 一手依据 |
|---|---|---|
| Avalonia 12 是当前 stable | ✅ 真 | `AvaloniaUI/Avalonia` 最新 release `12.1.2`（2026-09-02，`prerelease: false`） |
| compiled bindings 默认开启 | ✅ 真 | `docs/data-binding/compiled-bindings.md`：「If `<AvaloniaUseCompiledBindingsByDefault>` is undefined in your project file, **it defaults to `true` from v12**, but is `false` in earlier versions of Avalonia」 |

🔴 **spec 的怀疑从哪来，比结论本身更值得记**：它引的两份文档——`xaml/compilation.md`（「By default, data bindings use reflection…」）与 `migration/wpf/data-templates`（要求显式加 `<AvaloniaUseCompiledBindingsByDefault>true</...>`）——**都是未带版本限定语的滞后文档**。而正确的那一份带着 `from v12` 的限定语。

**操作判据**：官方文档内部互相矛盾时，先找哪一份带版本限定语（`as of version N` / `from vN onward` / `in earlier versions`）；无版本限定的那份通常是改版后未同步的历史遗留。⚠️ 搜索引擎的综述摘要也是二手，它会把两份矛盾文档「调和」成一句看着笃定的话（本次摘要即倾向「默认开启」，但同一段又照抄了矛盾句），必须拿具体措辞回原文核对。

⚠️ **连带结论**：既然「默认开启」为真，那么迁移 skill 缺的不是「版本声明修正」，而是下面遗留项 1 记的**迁移后果**。

### 本轮的判分口径变更（darwin dim8）

avalonia-wpf-migration 首评（`results.tsv`）改用新判分法，已写入 darwin-skill 的使用记录：**判官不再猜「哪一份输出用了 skill」，改为按该 skill `test-prompts.json` 每题的 `expected` 逐臂打分，臂别映射由实验者持有、最后由实验者算 Δ**。旧法迫使判官对实验设计做元推理，把「输出质量」替换成了「输出风格的实验设计推断」。

同轮两处必须记下的事实：

- 🔴 **判官会同向出错。** 两名判官独立断言「Avalonia 核心库有 `Avalonia.Controls.ListView`，缺的是 `GridView`」，且**两人都刚读过与之相反的 SKILL.md 正文**——是从 WPF 的 `ListView`/`GridView` 配对做的参数量记忆投射。回一手源（`main` 与 `release/11.3` 两分支的 `src/Avalonia.Controls` 目录列表均无该文件）判为误报，**SKILL.md 原文保留不动**。**独立判官互相印证不等于正确。**
- ⚠️ **判官数 ≥3 才看得出分歧结构。** 本次真实形态是 J1 与 J3 高度一致、J2 在 D/E/F 三臂上系统性偏高——只看前两名会把方差藏起来。这也是 baseline 从 71.9 更正为 72.4 的直接原因。
- ⚠️ **子 agent 的报告是延迟投递，不是丢失。** 本机链路下 `ListAgents` 显示 idle 而主上下文数分钟内无报告是常态；据「idle 且无报告」判丢失并重派替补，会多烧一轮判官成本，并用不完整的判官集写出之后必须更正的结论（本次即如此）。加速手段是**落盘**（prompt 里要求写进 `.tmp-*/scores-N.txt` 再读回），不要重发索要消息。落盘目录提交前必须删除。

**最有力的一条验证结果**：三名判官各自独立地对同一条 baseline 臂触发了一票否决，因为该臂断言「`TemplateBinding` 可以原样保留、语义与 WPF 一致」——**恰是本 skill 存在的意义所要防止的那个错误**。

### 结构维的判分口径变更：配对盲评（2026-09-15）

遗留项 1 的评分轮（PR #40）换了结构八维的测法。起因是一个**看起来像倒退的读数**：第 12 行记的基线是「换一批判官重测绝对值」，而新的 3 判官面板给出 70.1，比记录基线 72.4 低。诊断结果是**面板构成混淆，不是真倒退**——基线 530 出自 2 判官面板，新的 506.8 出自 3 判官面板；面板内离散度两者接近（约 30），面板间均值却差 23，且 dim6/dim2/dim4 三处「位移」全落在本次改动**物理上不可能触及**的维度上。

**改法**：同一批判官在**同一上下文里同时看到两版**，标签盲化、映射由实验者持有。判官严格度从组间变量降为组内变量，做差时相消。4 名判官 2-2 分配且**标签反向**（set1 记新版为 B、set2 记新版为 A）——这是设计里自带的安慰剂对照：若判官存在位置偏倚，两组 Δ 会反号。

结果 4/4 判新版、两种朝向同号，位置偏倚被证伪；逐官配对差 +31.5 / +25.5 / +37.5 / +26.5，均值 +30.25。**面板可比性有实测支撑而非感觉**：新 4 判官面板对同一份旧文件读数 523.25，与记录基线 530 仅差 6.75（折总分 0.68）——两套独立面板对同一文件读数吻合，这才是敢判「可比」的依据。

🔴 **可复用的两条**：

- **换判官组重测绝对值，结论不可直接与旧基线相减。** 面板间均值漂移可以大于真实 Δ（本次 23 vs 30，同一量级）。要么配对、要么如实记 `not-comparable`（第 9 行的先例）。
- **位移落在「改动不可能触及的维度」上，就是混淆的信号；落在改动针对的维度上，才是效应的形状。** 本次 dim1（frontmatter）与 dim4（检查点）位移恰为 `+0.000`，位移全部集中在改动针对的四维且以 dim7（完整性/架构）最大——而 dim7 正是旧版缺 `x:DataType` 入口这个**实质缺口**所在的维度。判官 pair-3 在不知哪版是新的前提下，独立复述出了该缺口原文（«neither the Quick Mapping Table nor any body section mentions `x:DataType` or `{ReflectionBinding}`»），与改动目标逐字吻合。
